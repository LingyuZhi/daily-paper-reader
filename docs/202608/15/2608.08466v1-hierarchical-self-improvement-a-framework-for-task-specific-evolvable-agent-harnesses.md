## 摘要
现代LLM智能体通常通过手动修改提示、工具或工作流来改进，而模型周围的可执行脚手架——即“支架”——在部署后通常被视为固定工件。本研究探讨了一种替代方案：支架是“任务特定且可连续进化的”：每个任务族维护自己的支架，通过固定的任务注入接缝在迭代间热切换，并利用环境反馈进行重写。我们引入了**分层自我改进（HSI）**框架，其中单个冻结的LLM $M$ 在三个分层范围内运行：执行任务的任务支架 $H$、重写 $H$ 的进化器，以及在冻结的外部锚点下重写进化器策略代码的元进化器。一种思考开/关设计通过禁用任务执行期间的推理而启用自我修改期间的推理，隔离了支架进化的贡献。HSI受两个因素约束：一个**反馈保真度界限**，因为进化需要信息丰富的奖励信号来指导选择；以及一个**骨干能力界限**，因为支架重新设计无法克服冻结模型的局限性。在BALROG上以DeepSeek-V4-Flash-Preview为冻结骨干，HSI在中等难度任务上相较于初始支架持续获得提升（BabyAI上+39.3，Crafter上+33.0，TextWorld上+25.0，MiniHack上+15.0，均为原始%进度），同时在BabaIsAI子套件上获得了强保留泛化能力（在20%未见分割的BreakStop上最佳测试为0.98，GoTo上为1.00）。对于超出骨干能力范围的任务（NLE），支架进化未提供任何改进。这些结果表明，任务特定支架进化是在明确经验界限下改进冻结LLM智能体的一个可行轴。代码可在 https://github.com/TailinZhou/hsi 获取。

## Abstract
Modern LLM agents are often improved by modifying prompts, tools, or workflows manually, while the executable scaffold surrounding the model---the \emph{harness}---is typically treated as a fixed artifact after deployment. This work studies an alternative where the harness is \emph{task-specific and continuously evolvable}: each task family maintains its own harness, which is hot-swapped across iterations through a fixed task-injection seam and rewritten using environment feedback. We introduce \textbf{Hierarchical Self-Improvement (HSI)}, a framework in which a single frozen LLM $M$ operates across three hierarchical scopes: a task harness $H$ that executes tasks, an evolver that rewrites $H$, and a meta-evolver that rewrites the evolver's strategy code under a frozen outer anchor. A thinking-on/off design isolates the contribution of harness evolution by disabling reasoning during task execution while enabling it during self-modification. HSI is bounded by two factors: a \emph{feedback-fidelity bound}, since evolution requires informative reward signals to guide selection, and a \emph{backbone capability bound}, since harness redesign cannot overcome limitations of the frozen model. On BALROG with DeepSeek-V4-Flash-Preview as the frozen backbone, HSI achieves consistent gains over the initial harness on moderate-difficulty tasks ($+39.3$ on BabyAI, $+33.0$ on Crafter, $+25.0$ on TextWorld, and $+15.0$ on MiniHack, all in raw \% Progress), while obtaining strong held-out generalization on BabaIsAI sub-suites ($0.98$ best-test on BreakStop and $1.00$ on GoTo from a $20\%$ unseen split). On tasks beyond the backbone's capability (NLE), harness evolution provides no improvement. These results demonstrate task-specific harness evolution as a viable axis for improving frozen LLM agents under clear empirical limits. Code is available at https://github.com/TailinZhou/hsi.

## 1. 核心问题与研究动机

- **背景与问题**：现代 LLM 智能体的性能高度依赖其外围可执行脚手架（Harness，包括提示词、工具编排、记忆、验证逻辑等），但现有方法通常将 harness 视为部署后固定不变的工件，改进依赖手动调优或外部更强的设计模型。
- **核心研究问题**：当底层 LLM 参数被冻结时，智能体能否**内生地（endogenously）自发进化自身 harness** 来提升任务性能？这种改进的真实上限是什么？

- **整体含义**：本文提出一种"任务特定、可连续进化"的 harness 范式——每个任务族维护一个自己的 harness，通过固定接口热切换、利用环境反馈重写，从而在不更新模型参数的前提下系统性释放冻结模型的潜在能力。

## 2. 方法论：Hierarchical Self-Improvement (HSI)

### 2.1 核心思想
- 使用**单个冻结 LLM M** 在三个层级范围内运作，通过分层结构实现"有界递归自我改进"：
  - **任务 Harness 层（H）**：执行任务，与环境的直接交互层。
  - **进化器层（Evolver）**：重写任务 harness H。
  - **元进化器层（Meta-Evolver）**：重写进化器策略 Σ。
- **冻结外部锚点**：元进化器自身的执行逻辑不可编辑，由不可变的初始化模板加载，防止不受限制的自引用。

### 2.2 关键设计原则
- **原则 1（单一冻结模型、三种 harness 范围）**：三个层级共享同一冻结模型 M、同一 prompt 格式和同一 react() 原语，仅工具集和执行上下文不同，通过显式内存边界隔离历史。
- **原则 2（自决探索-利用）**：框架不预设探索-利用调度，而是将其作为可进化策略的一部分交给模型自主决策；框架只提供原子交互原语、进化反馈信号和结构不变量。

### 2.3 五阶段进化循环
1. **种子选择（Seed Selection）**：从累积进化图 G_t 中选择祖先版本，生成结构化的进化假设（h_t），包含锚定版本、动机、预期改进方向和可证伪标准。
2. **主进化（Main Evolution）**：在假设引导下重写 H，生成 K 个候选版本，并通过任务执行获得环境奖励反馈。
3. **提交选择（Commit Selection）**：选择多样化候选池（而非仅最高奖励者），加入进化图并附语义理由。
4. **元进化（Meta-Evolution）**：修改进化器策略 Σ（种子策略、进化策略、提交策略、最终选择策略），使进化过程本身可适应。
5. **最优版本选择（Best-Version Selection）**：T 次迭代后，优先考虑泛化性，基于验证性能导出最终 harness。

### 2.4 关键技术细节
- **思考开关设计**：任务执行期间禁用扩展推理（固定模型单步能力上限），进化/元进化期间启用推理——隔离了 harness 进化与推理时计算的贡献。
- **LCB 奖励机制**：采用随机下置信界奖励 $r = \mu - z \cdot \sigma / \sqrt{n}$（z=0.5），降低高方差随机轨迹的影响。
- **热切换接口**：任务注入接口 `using_harness(agent, task)` 固定不变，内部组件可自由修改，保证版本可比较性。
- **记忆组织**：三层记忆体系——迭代局部记忆（plan.md）、持久进化记忆（BOOTSTRAP.md）、进化图记忆（累积版本关系图）。
- **探测机制**：通过压缩摘要检索历史轨迹（probe），在不超上下文预算的前提下利用长程进化历史。

## 3. 实验设计

### 3.1 Benchmark
- **BALROG**：长视界文本交互游戏基准，包含 6 个环境，覆盖不同能力需求和难度梯度：
  - BabyAI、BabaIsAI（指令跟随与导航）
  - Crafter（长视界规划、资源管理）
  - TextWorld（多步推理与操作）
  - MiniHack、NLE（艰难 roguelike 环境、稀疏反馈）
- 指标：episode 级 % Progress（0-100），进化时缩放到 [0,1]。

### 3.2 实验协议
- **Setup A（分布内进化）**：同一任务集用于进化和最终评估，每 episode 重采样新的环境种子。应用于 TextWorld、BabyAI、Crafter、MiniHack、NLE。
- **Setup B（留出泛化）**：BabaIsAI 子套件按子类别划分为开发/验证/测试，20% 测试分割在整个进化过程中不可见。应用于 BreakStop、GoTo、Make。

### 3.3 对比方法
- **Init Harness**：原始手工 harness 在相同骨干和协议下的对照基线（最主要的受控对照）。
- **meta-off 消融**：不启用元进化器，隔离"进化进化策略本身"的贡献。
- **BALROG 排行榜**：前沿模型的公开结果（如 Gemini-3-Pro、Grok-4、Claude-Opus-4.5、GPT-5 等），仅作上下文参考（不同骨干和配置）。
- 排除了外部提议者方法（如 Meta-Harness、AHE），因它们假设更强的外部模型，与 HSI 的固定骨干内生进化条件不同。

### 3.4 配置细节
- 骨干：DeepSeek-V4-Flash-Preview（API 服务），冻结。
- 进化：T=5 轮外部迭代，每轮最多 80 个 react() 步骤。
- 任务层：thinking 禁用、温度 0；进化器/元进化器：thinking 启用、最大推理力度。

## 6. 主要结论与发现

1. **HSI 在分布内显著提升性能**：meta-on 配置较 init harness 在 BabyAI 上 +39.3、Crafter 上 +33.0、TextWorld 上 +25.0、MiniHack 上 +15.0（% Progress），骨干和推理预算不变。
2. **可与前沿模型竞争**：TextWorld 上 65.0 超过 Grok-4（62.9）和 Claude-Opus-4.5-Thinking（59.0）；Crafter 上 44.6 超过 DeepSeek-R1（36.4）。
3. **元进化贡献明确**：meta-off→meta-on 在 TextWorld +19.0、MiniHack +10.0，证明进化策略本身的可进化性是重要增益来源。
4. **留出泛化成立**：BabaIsAI-BreakStop 0.98、GoTo 1.00 的 held-out 测试性能接近完美，证明进化发现的模式可迁移到未见任务。
5. **能力边界清晰**：NLE（近零奖励）上进化无有效改进；BabaIsAI-Make 提升有限（0.36）且方差大。
6. **进化动力学规律**：最大改进出现在第一轮迭代，后期增量递减；进化非单调（第 5 轮出现回归）。
7. **两条根本界限**：反馈保真度（需要信息丰富的奖励信号）和骨干能力（harness 重设计无法超越冻结模型的能力上限）。

## 7. 优点

- **方法论创新**：首次系统性地提出"三层分层自我改进"架构（harness / evolver / meta-evolver），在保持冻结外部锚点的前提下实现有界递归自我修改，解决了 Gödel 风格自指系统不可控的问题。
- **干净归因设计**：thinking-on/off 开关隔离推理计算与 harness 进化的贡献；固定任务注入接口保证版本可比较性；单一进化线谱（而非群体搜索）提高归因清晰度。
- **诚实的负面结果**：报告了 NLE 上的失败和 Make 上的有限改进，明确提出两大理论边界（反馈保真度、骨干能力），而非只展示正面结果。
- **泛化验证严谨**：Setup B 的 held-out 分割直接对应"进化获得的改进是记忆还是策略"的关键质疑。
- **任务特定的进化范式**：区别于追求通用 harness 的做法，提出每个任务族维护自身持续进化的 harness，并验证了同一任务族内跨任务的迁移性。
- **附录详实**：31 篇相关工作的系统调研、Per-suite 配置表、轨迹分析丰富了论证。

## 8. 不足与局限

- **骨干单一性**：仅用 DeepSeek-V4-Flash 一个模型，结论是否能推广到其他骨干（更弱/更强）未经验证。特别是相关工作中 Live-SWE-Agent 显示 GPT-5-Nano 自进化反而大幅退化，HSI 未测试这种"能力下限"。
- **基准范围有限**：仅 BALROG 一个基准（文本游戏），未覆盖代码生成、数学推理、工具使用等更广泛的 agent 场景。
- **计算成本未透明化**：进化过程涉及大量的 evaluate() 调用（每候选多 episode），总 API 成本和端到端时间未报告，实际部署的经济性不明。
- **统计可靠性存疑**：多数环境仅一次进化运行，最终测试的标准差只反映评估 episode 的噪声，未反映进化过程的随机性；LCB 参数 z=0.5 的选择依据未说明。
- **与外部方法的对比不完整**：HSI 的核心卖点之一是"相同冻结模型内生进化"，但未与同骨干下的外部提议者方法（如 Self-Harness）在同一条件下直接对比，无法量化"内生 vs 外导"的实际差距。
- **评估预算不对称**：进化期间候选 harness 使用较少 episodes（TextWorld 3 个、MiniHack/NLE 1 个），而初始 harness 最终评估用完整预算；初始 harness 基线可能被低估，导致增益夸大。
- **理论支撑不足**：虽引用 PAC 界限相关工作，但论文本身未提供理论刻画，未说明"达到什么条件时 harness 进化必然有效/无效"的形式化结果。
- **版本偏早**：arXiv 预印本（v1），未被同行评审；部分引用文献年份为 2026 年（未来日期，可能是预印本系统的一致标注），其真实性和可复现性有待验证。
- **扩展性存疑**：每任务族独立维护 harness 的范式在多任务、开放域场景下可能面临维护成本和可扩展性挑战。
