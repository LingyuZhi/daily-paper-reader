## 摘要
通用技能有望为语言智能体提供可复用的程序性知识，但语义相关性并不能保证执行效用：检索到的技能可能编码了与当前任务、执行环境或其他检索技能相冲突的假设。我们将此问题形式化为技能-执行错配（skill-execution misfit）。为解决这一问题，我们提出了SkillAligner，一种无需训练的执行时技能调整框架，将检索到的技能视为可调整的草稿，而非固定指令。在执行之前，SkillAligner进行一次性的联合调整，将有用的技能片段特化到任务需求上，使其程序性假设与可用的执行接口保持一致，并通过解决跨技能的依赖、冲突和冗余来组合生成的指导。调整后的内容被整合为一份紧凑的执行指南，并在后续轨迹中重复使用。跨多种智能体基准和模型主干的广泛实验表明，SkillAligner相对于现有技能使用基线显著提升了任务性能，在实例级别减少了技能引起的性能回退，并降低了总推理成本。

## Abstract
General-purpose skills promise reusable procedural knowledge for language agents, yet semantic relevance does not guarantee execution utility: a retrieved skill may encode assumptions that conflict with the current task, execution environment, or other retrieved skills. We formalize this problem as the skill--execution misfit. To address it, we propose SkillAligner, a training-free execution-time skill adaptation framework that treats retrieved skills as adaptable drafts rather than fixed instructions. Before execution, SkillAligner performs a one-time joint adaptation that specializes useful skill fragments to task requirements, aligns their procedural assumptions with the available execution interface, and composes the resulting guidance by resolving dependencies, conflicts, and redundancy across skills. The adapted content is consolidated into a compact execution guide and reused throughout the subsequent trajectory. Extensive experiments across diverse agent benchmarks and model backbones show that SkillAligner substantially improves task performance over existing skill-use baselines, reduces skill-induced regressions at the instance level, and lowers total inference cost.

# SkillAligner：在执行时将检索到的技能视为可调整的草稿

## 1. 核心问题与整体含义（研究动机与背景）

- **问题背景**：技能增强型智能体（skill-augmented agents）通过复用外部技能库中的程序性知识来提升任务执行能力。已有研究大量关注技能的生成、存储、检索和演化，但普遍假设“语义相关的技能就一定能用”。
- **核心矛盾**：作者通过实验发现，即使检索到的技能在语义上高度相关，也可能在实际执行中失效甚至造成性能倒退。他们将其形式化为**技能–执行错配（skill–execution misfit）**，即技能编码的假设与当前任务、执行环境或其他技能之间存在冲突。
- **三类错配来源**：
  - **技能间错配（inter-skill misalignment）**：多个技能之间逻辑冲突、重复或顺序不一致，例如一个技能要求按时间排序、另一个要求按值排序。
  - **技能–环境错配（skill–environment misalignment）**：技能依赖的工具、动作、资源或状态在当前执行环境中不可用。
  - **技能–任务错配（skill–task misalignment）**：技能的具体目标或约束与当前任务需求不完全匹配。
- **关键洞察**：现有方法大多在具体执行实例出现前就把技能“定型”，无法适应每次执行中变化的查询、环境和技能组合。因此，作者主张**将检索到的技能视为可调整的草稿，在执行时对其进行临时调整**，而不是当作固定指令。

## 2. 方法论：SkillAligner

- **总体框架**：SkillAligner 是一个**不依赖训练（training-free）**的执行时技能调整框架。它在执行前进行一次性的联合适应调用，将检索到的技能转换为紧凑的执行指南 H，供后续整个轨迹使用。
- **形式化流程**：
  - 输入：任务查询 q、检索到的技能集 S_q、执行规范 E（描述可用工具、动作格式、资源、权限等）。
  - 一次调用生成指南：H = SkillAligner(q, S_q, E)。
  - 执行阶段仅使用 H：a_t ∼ M(q, o_t, H)，其中 M 为冻结的骨干模型，o_t 为逐步观测。
- **三个阶段**：

  ### 2.1 任务接地（Task Grounding）
  - 从查询 q 中提取**任务契约 τ**，包括目标、硬约束、软偏好、已知输入、期望输出和未明确条件。
  - 将每个检索到的技能分解为原子片段，并按与任务的匹配度分类：
    - **核心（core）**：通用且与任务一致；
    - **任务绑定（task-bound）**：直接支持目标或约束；
    - **弱相关（weak）**：压缩处理以降低上下文负担；
    - **丢弃（dropped）**：与硬约束冲突或无关的内容。
  - 仅当查询明确支持时，才将通用步骤绑定到任务实体；保留片段间的原始顺序，除非与任务契约冲突。

  ### 2.2 执行环境对齐（Execution-Environment Alignment）
  - 将任务接地后的技能与执行规范 E 进行匹配，检查前置条件与可用工具、动作格式、资源、权限是否一致。
  - 对可本地修复的不匹配（如等价接口替换）进行**重写**；无法安全修复且改变任务意图的技能被标记为 `Abstain` 并丢弃。
  - 每个技能被分配使用模式：
    - **直接（Direct）**：可安全执行；
    - **条件（Guarded）**：运行时才能验证，保留为条件检查、警告或回退；
    - **放弃（Abstain）**：核心假设与环境冲突且无法修复。

  ### 2.3 技能组合（Skill Composition）
  - 识别剩余技能之间的**依赖（dependency）**、**冲突（conflict）**和**重叠（overlap）**关系。
  - 依赖决定执行顺序；重叠进行合并去重；冲突按“任务硬约束 > 执行规范 > 技能指导”的优先级解决，被否定的替代方案转为显式的 `Avoid` 规则。
  - 输出最终指南 H，包含四个字段：
    - `Primary`：主执行路线与支持过程；
    - `Checks`：需要从观测验证的前置条件；
    - `Avoid`：不支持的假设、无效动作或冲突指令；
    - `Fallback`：主路线受阻时的替代策略。

- **关键特点**：上述三个阶段在一次 LLM 调用中联合完成，不存储中间结构；生成的指南固定且紧凑，只暴露给执行智能体，原始技能不再直接注入。

## 6. 主要结论与发现

- 检索到的技能即使语义相关，也可能因与任务、环境或其他技能冲突而**伤害执行**，且该现象在不同基准和骨干模型上普遍存在（回归率 5.80%–17.91%）。
- 回归原因分布：技能–任务错配占 38.55%，技能间错配占 28.59%，技能–环境错配占 26.71%，其余 6.15%。
- SkillAligner 在所有 9 个主实验设置中均取得最佳性能，均值 58.17，比最强基线 SkillPyramid 高 3.92，比直接注入原始技能高 11.10。
- SkillAligner 显著降低技能导致的实例级回归（如 Qwen3-8B 上 ALFWorld 回归率从 17.91% 降到 2.24%），同时保持或提升转移率。
- 推理成本下降：适应开销被更高效执行带来的 token 节省抵消，总成本平均节省 38%。
- 消融表明三个调整阶段互补，联合应用效果远超任何单一阶段；技能库规模变化不影响方法有效性，但最优规模因任务而异。

## 7. 优点

- **概念创新**：首次明确形式化“技能–执行错配”并分解为三种可诊断的错配来源，为技能使用提供了新的理论视角。
- **方法轻量且实践性强**：无需训练，不修改技能库，不改变检索器，仅需一次额外的 LLM 调用，即可重用至整个执行轨迹。
- **执行时适应性**：相比固定技能或持久化技能精化，SkillsAligner 能够针对当前查询、环境和其他技能做即时特化，弥补现有方法的根本局限。
- **统一的紧凑输出**：四字段指南（Primary/Checks/Avoid/Fallback）可解释性强，便于后续验证和调试。
- **实验设计严谨**：统一的评估协议、配对实例分析、实例级 Transfer/Regression 指标、详细消融与成本核算，结论可靠。
- **成本考量充分**：不仅报告性能，还量化了适应开销与总成本节约，展示“对齐”并非额外负担而是净收益。

## 8. 不足与局限

- **一次性调整的局限**：SkillAligner 只在执行前做一次调整，无法应对执行中途涌现的新错配（例如环境状态变化或技能在中间步骤的意外失效）。作者在讨论中也承认此点，并指出未来需考虑选择性在线修订与 KV 缓存代价。
- **依赖检索质量**：虽然方法对各种技能内容鲁棒，但所有实验固定使用 BM25 和 k=5，未考察不同检索器或检索噪声的影响；若检索结果完全无关，调整效果可能有限。
- **实验场景有限**：仅覆盖三个英文基准（具身操作、网页购物、QA），未涉及多模态、代码执行、真实 API 调用等更复杂场景。
- **技能库构建偏差**：技能库主要来自社区仓库和 SkillsBench，可能偏向特定风格和语言，对非英语任务或专业领域适用性未知。
- **成本测量维度单一**：只统计 token 数，未报告墙钟时间或 API 实际费用；对于长轨迹任务，单次适应调用的延迟可能影响端到端响应时间。
- **案例研究的通用性**：详细案例集中于 WebShop，虽然能清晰展示三类错配，但缺少 ALFWorld 和 SearchQA 的深度案例分析，可能削弱对具身与问答场景的直观解释力。
- **对强模型的有效性需进一步验证**：虽然实验包含 Gemini 2.5 Pro，且指出强模型也可能遵循错配技能，但并未探索极强推理模型（如未来更大规模）下的边际收益是否衰减。
