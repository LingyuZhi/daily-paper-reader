## 摘要
长视界工具使用智能体必须对用户目标、领域策略、工具调用、模拟器状态以及延迟的可验证奖励进行推理。强化学习（RL）天然适用于这一场景，但多轮同策略推出会产生长上下文，而模型特定的注意力层可能需要自定义掩码和学习到的sink归一化。我们提出了SINKFLEX-RL，一个用于双控制工具使用环境中的强化学习的模块化训练系统。该系统结合了与Gymnasium兼容的环境封装器、VERL风格的推出数据流、无需独立价值模型的组相对策略优化，以及一条感知sink的FlexAttention路径，该路径旨在在因果掩码和滑动窗口掩码下保持模型特定的sink缩放。在初步的Tau2Bench零售运行中，验证奖励（mean@1）从训练早期的0.25上升到观测训练窗口后期的0.44，同时训练得分和轨迹奖励代理指标也呈上升趋势。在固定配置的内存基准测试中，优化后的注意力路径在4096个令牌时将峰值显存从28.06GB降至22.52GB，降低了19.7%，并在实测的8192令牌配置下使用25.53GB运行，而急切（eager）基线则内存不足。这些结果说明了将环境接口、强化学习数据流和注意力内核设计相结合对于内存可行的长视界智能体训练的价值。

## Abstract
Long-horizon tool-using agents must reason over user goals, domain policies, tool calls, simulator state, and delayed verifiable rewards. Reinforcement learning (RL) is a natural fit for this setting, but multi-turn on-policy rollouts create long contexts, while model-specific attention layers may require custom masks and learned sink normalization. We present SINKFLEX-RL, a modular training system for RL in dual-control tool-use environments. The system combines a Gymnasium-compatible environment wrapper, a VERL-style rollout dataflow, group-relative policy optimization without a separate value model, and a sink-aware FlexAttention path designed to preserve model-specific sink scaling under causal and sliding-window masks. In a preliminary Tau2Bench retail run, validation reward (mean@1) rises from 0.25 early in training to $0.44$ later in the observed training window, while training-score and trajectory-reward proxies also trend upward. In a fixed-configuration memory benchmark, the optimized attention path reduces peak VRAM from 28.06GB to 22.52GB at 4096 tokens, a $19.7\%$ reduction, and runs the measured 8192-token configuration using $25.53$~GB where the eager baseline runs out of memory. These results illustrate the value of integrating environment interfaces, RL dataflow, and attention-kernel design for memory-feasible long-horizon agent training.

## 2. 方法论

- **总体框架**：SINKFLEX-RL 由四个核心组件组成：
  1. Gymnasium 兼容的双控制环境封装器；
  2. VERL 风格的 rollout 数据流；
  3. 基于组相对策略优化（GRPO）的策略更新，无需独立价值模型；
  4. Sink-aware FlexAttention 注意力路径，支持因果掩码和滑动窗口掩码。
- **环境封装器**：将每个 benchmark 域统一为 `reset/step` 接口。`reset` 时采样任务、初始化共享状态；`step` 时解析模型输出（自然语言回复、工具调用或终止），推进用户模拟器和状态后端，并返回下一观测和奖励元数据。这样将 benchmark 特定的用户模拟、工具行为与检查逻辑与训练器解耦。
- **Rollout 数据流**：Rollout worker 持有策略循环，逐轮格式化观测、采样动作、解析响应、追加轨迹，直到终止或达到最大轮次。训练器接收 token 级 log 概率、动作掩码、轨迹奖励和元数据，不依赖 benchmark 特定解析逻辑。
- **GRPO 更新核心公式**：
  - 组归一化优势：  
    \(\hat{A}_i = \frac{R_i - \mu(R_{1:G})}{\sigma(R_{1:G}) + \epsilon_A}\)
  - 重要性采样比率：  
    \(\rho_{i,t}(\theta) = \frac{\pi_\theta(y_{i,t} | x, y_{i,<t})}{\pi_{\theta_{old}}(y_{i,t} | x, y_{i,<t})}\)
  - 裁剪损失（目标函数）：  
    \(J_{i,t}(\theta) = \min\big(\rho_{i,t}(\theta)\hat{A}_i,\ \mathrm{clip}(\rho_{i,t}(\theta), 1-\epsilon_c, 1+\epsilon_c)\hat{A}_i\big)\)
  - 总损失包含 KL 正则项：  
    \(L_{GRPO}(\theta) = -\frac{1}{\sum_i T_i} \sum_i \sum_t J_{i,t}(\theta) + \beta D_{KL}(\pi_\theta \| \pi_{ref})\)
- **Sink-aware FlexAttention**：
  - **零值 sink 等价变换**：不显式向 KV 缓存中添加 sink token，而是将“显式零值 sink 的 softmax 输出”代数等价为“标准注意力的输出乘以一个缩放因子”：
    \[
    O_{sink} = \sigma(\ell - s_\eta) O_{std},\quad \ell = \log\sum_i \exp(q\cdot k_i)
    \]
  - **掩码设计**：组合因果掩码、滑动窗口约束和始终可见的前缀：
    \[
    M_{b,h,q,k} = 1[k \le q] \land 1[q - k \le w \lor k < p]
    \]
  - **实现模式**：FlexAttention 返回输出和 log-sum-exp 统计量，之后应用学习到的 sink 缩放函数 \(z' = z \odot f_\eta(\ell)\)。
  - **梯度流**：通过链式法则将 \(z'\)、\(\alpha_{sink}\)、\(\ell\)、\(\eta\) 的梯度连接起来，并在 `torch.compile`/AOTAutograd 下编译，避免 \(O(n^2)\) Jacobian 的物化。
  - **内存优化**：使用 `torch.compile` 融合 sink-rescaling 点运算，并在块掩码构造中省略显式 batch/head 维度，依靠 kernel 侧广播，避免掩码元数据重复存储。

## 3. 实验设计

- **实验 1：τ2-Bench 零售域初步训练**
  - 基准：τ2-Bench（双控制环境，代理和模拟用户均可影响任务状态）。
  - 任务：零售域中，代理通过 API 调用、多轮对话和标准操作流程（SOP）完成用户目标。
  - 监控指标：
    - 验证奖励（mean@1）：程序化验证的任务成功率；
    - 训练得分代理（dashboard 标记为“critic-style score”，但实际无价值模型）；
    - 轨迹奖励代理（滚动平均的原始 episode 奖励）。
  - 结果估计：验证奖励从训练早期的 0.25 上升到后期的 0.44；训练得分代理和轨迹奖励代理分别从 0.18 上升至 0.40 和 0.39。
- **实验 2：峰值内存基准**
  - 对比方法：模型原生 eager 注意力参考路径 vs. 优化的 sink-aware FlexAttention 路径。
  - 固定模型、批大小和训练配置，序列长度分别为 1024、2048、4096、8192 tokens。
  - 结果：
    - 1024：21.07 GB vs. 20.11 GB（节省 4.5%）；
    - 2048：23.27 GB vs. 21.02 GB（节省 9.7%）；
    - 4096：28.06 GB vs. 22.52 GB（节省 19.7%）；
    - 8192：eager 基线 OOM，优化路径在 25.53 GB 下完成。
- **实验性质**：实验 1 是初步训练行为记录，不是算法比较；实验 2 只测量峰值显存，不测吞吐或端到端时间。

## 6. 主要结论与发现

- **训练信号有效**：在初步零售训练运行中，验证奖励（mean@1）从 0.25 上升到 0.44，训练得分和轨迹奖励代理同步上升，说明 GRPO 更新能够从程序化奖励中获取学习信号。

- **论文结论收窄**：结果支持“环境-数据流-内核集成能改善内存可行性”的窄化主张，但不支持算法优越性、广泛泛化性或端到端速度提升等更宽泛结论。

## 7. 优点

- **模块化设计**：环境封装器将 benchmark 逻辑与训练器解耦，便于扩展到其他可执行环境。
- **无价值模型的 GRPO**：避免训练独立 critic/value 网络，显著减少内存和计算开销，适合大型语言模型。
- **Sink-aware 注意力保持模型语义**：通过零值 sink 的代数等价，避免了显式 sink token 物化，同时保持训练前向/后向路径中的 sink 缩放行为。
- **可编程注意力内核**：利用 FlexAttention 的块稀疏掩码和 `torch.compile` 融合，兼顾灵活性与计算效率。
- **内存优化细节**：如掩码元数据的 batch/head 广播、避免 eager 中间张量，对实际显存节省有直接贡献；8192 tokens 下能完成而 eager 失败的对比很有说服力。
- **实验目标明确**：作者明确界定“初步训练行为”和“仅测峰值显存”，避免过度解读，学术表述谨慎。
