## 摘要
自演化智能体通过追加成功流程和失败修复来积累可重用技能。随着时间的推移，相同的要求常常在多个分支、示例和警告中重复表述，而常见的动作序列被复制而非重用。由此产生的技能变得注入成本高昂且难以维护。通用提示压缩并不适合这一场景，因为技能不是一段扁平的文本：其名称和描述定义了适用条件，其工作流控制执行，其工具和输出契约约束有效性，并且即使没有采样任务激活，罕见异常也可能仍然至关重要。评估引导的压缩可以测试这些行为，但它引入了模拟回放、成本以及对压缩时评估集的依赖。我们提出了SkillZip，一种无评估方法，通过寻找技能最短的忠实结构解释来压缩技能。其直觉是“一次解释，多次引用”：在适用范围内只陈述一次重复规则，将重复的动作序列分解为共享流程，并仅将差异作为显式异常保留。我们将这一直觉形式化为一个带类型的、关于技能契约和残差的最小描述长度目标，并受制于对每个提取的触发器、工作流边、工具要求、义务和输出字段的硬覆盖约束。该公式提供了简单的共享阈值，通过构造保留了独特的罕见规则，并支持高效的局部更新。SkillZip具有一次性模式，包含一次结构化提取调用和确定性优化，以及持续性的Zip-on-Write模式，无需回放任务或重新解析完整历史即可整合每个自演化补丁。通过全面的实验评估，我们展示了SkillZip在压缩性能、泛化能力和成本开销方面的有效性和优越性。

## Abstract
Self-evolving agents accumulate reusable skills by appending successful procedures and failure fixes. Over time, the same requirement is often restated in several branches, examples, and warnings, while common action sequences are copied rather than reused. The resulting skill becomes expensive to inject and difficult to maintain. Generic prompt compression is ill-suited to this setting because a skill is not a flat passage: its name and description define when it applies, its workflow controls execution, its tool and output contracts constrain validity, and rare exceptions may remain essential even when no sampled task activates them. Evaluation-guided compression can test these behaviors, but it introduces rollouts, cost, and dependence on the compression-time evaluation set. We present SkillZip, an evaluation-free method that compresses a skill by finding its shortest faithful structural explanation. The intuition is explain once, reference many: state a repeated rule once at the scope where it applies, factor a repeated action sequence into a shared procedure, and keep only the differences as explicit exceptions. We formalize this intuition as a typed minimum description-length objective over a skill contract and a residual, subject to a hard coverage constraint for every extracted trigger, workflow edge, tool requirement, obligation, and output field. The formulation provides simple sharing thresholds, preserves unique rare rules by construction, and supports efficient local updates. SkillZip has a one-shot mode with one structured extraction call and deterministic optimization, and a continual Zip-on-Write mode that integrates each self-evolution patch without replaying tasks or reparsing the full history. Through comprehensive experimental evaluations, we demonstrate the effectiveness and superiority of SkillZip in compression performance, generalizability, and cost overhead.

## 1. 核心问题与整体含义（研究动机和背景）

自演化智能体（self-evolving agents）通过不断追加成功流程、失败修复、警告和示例来积累可重用的技能。这种更新方式看似合理，但随着时间推移，会导致一个系统性矛盾：

- **文本增长与程序性知识增长脱节**：相同的要求经常在多个分支、示例和警告中重复表述，常见的动作序列（如 validate–repair–verify）被反复复制，而非复用。研究显示，技能长度在新程序性内容趋于饱和后仍在持续增长（平均增长约 5.2 倍）。
- **技能膨胀的实际危害**：技能在每次调用时都占用上下文窗口，冗余文本增加了 prefill 成本，并且会模糊真正控制执行的指令，让技能变得难以维护。
- **现有方法不适用**：
  - 通用提示压缩（如 LLMLingua）按 token 重要性筛选，但技能不是扁平文本，其语义分布在名称、触发条件、工作流、工具参数、分支守卫、输出约束等结构化契约中，低频率的罕见异常可能比高频率冗余段落更不可删除；
  - 评估引导的压缩（如 SkillReducer）虽然可以恢复被遗漏的内容，但依赖压缩时的任务采样、rollouts 和验证器，成本高昂，且存在对评估集的过拟合风险。
- **核心研究问题**：能否仅利用技能自身已有的结构信息，在不观察任务、奖励、轨迹或验证器的情况下，对技能进行忠实且有效的压缩？

论文提出的答案是 **SkillZip**——一种无评估（evaluation-free）的压缩方法，通过发现技能中可复用的结构，找到技能“最短的忠实结构解释”。

## 2. 方法论

### 2.1 核心思想

SkillZip 的核心直觉是 **“一次解释，多次引用”（explain once, reference many）**：

- 将重复规则在适用作用域中只陈述一次；
- 将重复的动作序列因子化为共享流程；
- 仅把真正的差异保留为显式异常。

本质上，这与“将三段重复代码重构为一个函数 + 三次调用”的代码重构思想一致。形式化上，这被建模为**类型化最小描述长度（Minimum Description Length, MDL）目标**。

### 2.2 技能契约表示

SkillZip 将技能视为一个类型化契约（typed contract）：

$$C(S) = \langle I, G, T, C, O, E \rangle$$

其中：
- **I**：接口——技能名称、用途、积极触发器、排除条件；
- **G**：工作流——动作、顺序、决策、循环、回退、停止条件；
- **T**：工具协议——工具名称、必需参数、前置条件、预期观察、错误处理；
- **C**：作用域规则——必须/禁止/偏好做什么，以及适用的作用域和守卫；
- **O**：输出契约——响应类型、必填字段、排序、验证、完成条件；
- **E**：支持证据——与契约元素关联的示例、模板、理由。

每个解析出的单元记录为：类型 $\tau$、作用域 $\sigma$、守卫 $g$、模态 $m$、归一化内容 $p$ 和来源片段 P。无法置信解析的片段被放入**锁定残差（locked residual）**，原文保留、禁止删除。

### 2.3 核心公式

SkillZip 的目标是最小化渲染成本，同时满足硬覆盖约束：

$$(K^*, R^*) = \arg\min_{(K,R)\in H(S)} \left[ L(K) + L(R|K) \right] \quad \text{s.t.} \quad \forall a \in A_{req}(S): a \preceq (K, R)$$

其中：
- $K$ 是可复用契约元素库（共享规则、工作流片段、工具契约、输出字段）；
- $R$ 是残差（独特、异常或不确定内容）；
- $L(\cdot)$ 是渲染 token 成本，包含定义、引用、作用域注解的开销；
- 覆盖关系 $\preceq$ 是类型敏感的（工具名不覆盖其必需参数；通用规则不覆盖冲突的守卫异常）；
- **硬覆盖约束**保证：独特规则不能因为“简短”或“不被采样任务激活”而被删除（推论 IV.2：罕见规则的保留不依赖于任何压缩时任务分布）。

### 2.4 四个统一的结构决策

同一个 MDL 目标统一驱动四种压缩形式：

| 决策类型 | 内容 | 收益条件（简化） |
|---|---|---|
| 等价需求合并 | 同义改写合并为一个共享规则 | $L(z) + L(x_1\|z) + L(x_2\|z) < L(x_1) + L(x_2)$ |
| 跨作用域规则提升 | 规则上移到最近公共祖先作用域 | $L(c@u) + rL(\text{scope-ref}) < \sum_{i} L(c@s_i)$ |
| 工作流复用 | 重复动作序列变为共享流程 | $L(def(q)) + rL(call(q)) < rL(q)$ |
| 公共规则+异常 | 相似守卫变体合并为公共规则+显式差异 | $L(c) + \sum_i L(\delta_i) < \sum_i L(c_i@g_i)$ |

### 2.5 两种工作模式

**（1）One-Shot SkillZip（一键压缩）**：
1. 确定性扫描器解析 Markdown 结构（front matter、标题、嵌套列表、代码块等），生成编号块和稳定 ID；
2. 调用一次结构化提取模型，恢复类型化契约（schema-constrained，需引用来源块）；
3. 类型兼容的候选生成：哈希精确匹配 + 嵌入检索近似匹配 + 冻结关系检查器（预测等价/蕴含/冲突/无关），冲突产生异常候选而非合并候选；
4. 确定性优化：等价单元聚类 → 动态规划求解作用域放置 → 加权集合打包选择工作流复用；
5. 固定模板渲染 + 可选结构审计（重新解析压缩后的技能并与所选契约对比，缺失则恢复最短来源片段并锁定）。

**（2）Zip-on-Write（持续压缩）**：自演化智能体产生新补丁时，SkillZip 将补丁与当前契约的兼容部分比较，提供四种操作：
- **ABSORB**：补丁重复了现有要求，无新增契约内容；
- **REFINE**：补丁为现有单元增加守卫、工具参数、验证或显式异常；
- **EXTEND**：补丁引入全新要求；
- **REFACTOR**：补丁使共享规则或流程变得划算。

候选搜索仅限匹配的类型、当前作用域、祖先作用域和相邻工作流节点（$O(dk)$ 复杂度），支持高效局部更新；当可恢复节省超过阈值、契约增长超阈值或到达补丁数阈值时触发全局重打包。

### 6. 主要结论与发现（续）

4. **效率优势明显**：平均 3.5× 加速，零任务 rollout，避免了对评估集的依赖和过拟合**风险**；同时压缩过程所需的 LLM 调用次数更少（4–8 次 vs 40–80+ 次 rollout 调用），并且优化与渲染环节完全确定性，便于复现和集成到自演化循环中。

5. **跨模型泛化能力稳定**：在 RQ4 的源–目标模型矩阵中，压缩后的技能从源模型迁移到其他骨干模型（包括跨家族模型）时，任务性能与未压缩技能基本持平或仅小幅波动。这表明 SkillZip 提取的是与具体模型无关的契约化结构（规则、流程、工具协议），而非针对某个模型的隐性记忆或表面措辞，因此压缩收益可以随技能本身一起跨模型复用。

6. **持续压缩（Zip-on-Write）可有效遏制技能膨胀**：在 LiveMath 的 16 轮演化实验中，无论压缩在第 1 轮还是第 8 轮激活，技能规模增速都被显著抑制，且任务性能不降或略有提升。这验证了“补丁级局部更新 + 阈值触发全局重打包”的设计：日常演化中只需低成本局部操作（ABSORB/REFINE/EXTEND/REFACTOR），在冗余累积到阈值后再进行全局整理，从而将 MDL 优化的代价平摊到整个演化过程中。

## 7. 局限性与未解决问题

尽管 SkillZip 在三个基准上表现稳定，但论文仍存在若干局限性：

1. **组件消融缺失**：论文没有单独剥离类型化契约表示、硬覆盖约束、MDL 长度模型、局部更新策略等组件来衡量各自的独立贡献。因此，当前性能是整体设计的结果，尚不清楚哪一部分对“保真 + 压缩”的贡献最大。

2. **阈值与超参数敏感性未分析**：MDL 长度模型中的代价因子、全局重打包触发阈值等关键超参数只给出了固定设定，未报告敏感性分析。不同技能规模、不同语言风格下，最优阈值可能不同，这会影响 SkillZip 直接迁移到新场景时的鲁棒性。

3. **无人工质量评估**：压缩后技能的“可读性”和“可维护性”未被人类评估。虽然任务性能和压缩率客观证明了契约保真度，但程序性技能最终仍由人（或下游智能体）阅读和迭代，语义清晰度同样是重要维度。

4. **演化器覆盖有限**：主实验仅使用 SkillOpt 作为演化器；RQ1 中虽然引入了 Memento-Skills 验证膨胀现象，但没有对不同演化器产生的技能做压缩对比。不同演化策略产生的冗余类型可能不同（例如更多示例堆积 vs 更多分支复制），SkillZip 对此是否同样鲁棒仍待验证。

5. **技能规模与演化轮数有限**：最长演化 16 轮，技能平均数千 token；对于更长生命周期、更大体积的程序性技能库，锁存残差的规模、局部更新的累积误差、重打包的计算成本都可能在更大尺度上成为瓶颈。

6. **基准技能形态相对同质**：三个基准的技能都以 Markdown 文本承载，结构以列表、代码块、嵌套标题为主；对于高度形式化的代码型技能、多模态技能或带状态依赖的交互式技能，解析器和契约模型需要额外适配。

## 8. 意义、启示与未来方向

**理论意义**：SkillZip 将“技能压缩”从带评估信号的采样优化问题，重新定义为可利用技能自身结构信息的类型化 MDL 优化问题。这一视角更贴近程序代码重构中的“去重 + 抽象”思想，也解释了为何演化技能会持续膨胀——因为追加补丁比重构规则在局部更容易，而全局去重需要显式机制。

**实践启示**：对于自演化智能体的工程实现，Zip-on-Write 表明压缩不必是“事后一次性大扫除”，而可以作为智能体写入路径上的内置环节。四种补丁操作（ABSORB/REFINE/EXTEND/REFACTOR）本身就是对技能演化的语义分类，可作为日志、审计或增量索引的基础。

**未来方向**：

- 将 SkillZip 推广到多技能库级别的全局压缩，在技能之间发现共享工作流和工具协议；
- 引入自适应超参估计，用技能自身的统计特征（重复率、分支密度、残差比例）决定 MDL 代价权重和重打包阈值；
- 与验证器结合但保持评估无关性：在允许低成本验证的场景中，将保真度检查从“压缩前采样”改为“压缩后抽查”，避免过拟合；
- 将锁定残差机制扩展为“可解释的保留原因”元数据，例如记录“因解析置信度低”或“因与现有契约冲突”而保留，辅助用户审计；
- 将压缩后的技能表征接入更细粒度的能力复用系统，例如将共享工作流从技能中抽离为独立可调用的库函数，进一步减少引用成本。

总体而言，SkillZip 提供了一种可行且可扩展的技能压缩范式，在不依赖任务分布和验证器的情况下，同时实现了高压缩率、性能保真与跨模型稳健性，为长生命周期自演化智能体的知识管理提供了一个实用的基础设施。
