## 摘要
自进化智能体通常围绕预设的优化流水线构建：框架决定如何收集证据、修改持久化工件、选择候选方案以及何时停止。我们探究当前沿模型作为优化器时，这种任务特定的流程是否仍有必要。我们引入开放式优化（OEO），它保持目标、允许的交互、资源预算、数据边界和评估不变，同时允许优化器在线组合改进过程。我们将OEO与两种互补的预设方法进行比较：SkillOpt（一种带有有界编辑的分阶段流水线）和GEPA（一种反思性进化搜索）。在8个基准-目标模型设置上的14项直接对比中，由GPT-5.5驱动的OEO取得了12胜1平1负（差距0.21个百分点）的成绩。其使用的目标交互令牌预算中位数为SkillOpt配置的34.3%。一次性、零交互的对照实验表明，这些收益并非由单次基于先验的重写所解释。然而，委派存在能力边界：使用中等能力的优化器时，SkillOpt优于OEO；而弱优化器则无法通过不变的OEO接口运作。在完全仪器化的OEO-SkillOpt对比中，轨迹分析进一步表明，预设对优化过程的影响比对最终行为的影响更一致。这些发现共同将预设流水线重新定义为依赖能力的支架：必要的约束仍然是外部的，但足够强大的优化器可以从可测量的反馈中组合出通往持续改进的路径。

## Abstract
Self-evolving agents are usually built around prescribed optimization pipelines: the framework decides how to gather evidence, revise a persistent artifact, select candidates, and stop. We ask whether this task-specific procedure remains necessary when a frontier model acts as the optimizer. We introduce Open-Ended Optimization (OEO), which keeps the objective, permitted interactions, resource budget, data boundary, and evaluation fixed while allowing the optimizer to compose the improvement process online. We compare OEO with two complementary prescribed approaches: SkillOpt, a staged pipeline with bounded edits, and GEPA, a reflective evolutionary search. Across 14 head-to-head comparisons over 8 benchmark-target-model settings, GPT-5.5-driven OEO records 12 wins, 1 tie, and 1 narrow loss of 0.21 percentage points. It uses a median 34.3 percent of SkillOpt's configured target-interaction token budget. A one-shot, zero-interaction control shows that the gains are not explained by a single prior-driven rewrite. However, delegation has a capability boundary: SkillOpt outperforms OEO with a medium optimizer, and a weak optimizer cannot operate through the unchanged OEO interface. In the fully instrumented OEO-SkillOpt pair, trajectory analysis further shows that prescription changes how optimization proceeds more consistently than it changes final behavior. Together, these findings recast prescribed pipelines as capability-dependent scaffolding: essential constraints remain external, but a sufficiently capable optimizer can compose the route from measurable feedback to persistent improvement.

## 1. 论文的核心问题与整体含义（研究动机和背景）

- **背景**：自进化智能体的核心承诺是“将经验转化为持续改进”。现有的自进化系统通常围绕**预设优化流水线**构建，即框架不仅要指定“要改进什么”，还要指定“如何改进”——包括收集哪些证据、如何诊断失败、提出什么修订、保留哪些候选、何时停止等。
- **核心问题**：当前沿模型（如 GPT-5.5）足够强大时，这种任务特定的优化流程是否仍然必要？换言之，**优化责任应该放在哪里**——是放在框架的预设流程中，还是交给模型在线自主组合？
- **核心概念区分**：
  - **优化契约（Optimization Contract）**：外部固定的要素（目标、初始技能、目标模型、允许的数据与操作、资源预算、冻结评估器、封存测试集），由框架掌控。
  - **优化元策略（Optimization Meta-Policy）**：任务特定、组织证据→修订→选择→停止的逻辑，传统上由框架预设。
- **整体含义**：论文主张重新审视预设流水线的必要性，并提出一种“能力自适应”的分工原则：**强优化器可以自主规划改进路径，弱优化器仍需外部脚手架支持**。该研究挑战了自进化智能体设计中的一个隐含前提——任务特定流程必须由框架预设。

## 2. 论文提出的方法论：核心思想、关键技术细节

### 2.1 开放式优化（OEO）的核心思想
- OEO 固定外部优化契约（目标、权限、预算、数据边界、评估器），但**不预设**任何任务特定的优化元策略（无反思模板、无编辑语言限制、无候选调度、无停止规则）。
- 优化器在每轮观察当前技能、累积证据、提交过的检查点（checkpoints）和剩余资源，然后自主选择一个合法操作。
- 允许的操作集包括：检查证据、执行目标模型的一次定向 rollout、修订或重写技能、选择历史检查点作为最终输出、停止等。
- OEO 的关键特征是**代理性实验设计**：它不是“无约束的开放式”，而是“契约约束下的在线过程组合”。

### 2.2 形式化描述
- 每种方法 q 通过过程特定的动作接口 I_q 暴露契约允许的操作 O，优化元策略选择：

  a_t = μ^(q)(z_t; M_opt, C, I_q)

  其中 z_t = (s_t, H_t, K_t, b_t) 表示当前技能、观测历史、已提交检查点、剩余资源。

- **保持固定**：目标、初始技能 s₀、目标模型、允许的选择数据、允许的操作集 O、资源预算 B、冻结评估器、封存测试集。
- **被委派**：证据收集顺序、诊断方式、修订策略、候选选择、停止时机。

### 2.3 两个代表性预设方法
- **SKILLOPT**：分阶段训练流水线——固定 rollout/反思批次、将成败分离诊断、限制为有界补丁操作符（bounded patch operators）、仅提交通过验证改进门控的候选。代表“流水线中心”的预设方式。
- **GEPA**：反思性进化搜索——允许自由形式的文本突变，但将其放入框架定义的 Pareto 进化循环中（父代选择、评估节奏、种群保留、终止条件由框架控制）。代表“搜索中心”的预设方式。

### 2.4 OEO 执行流程（ Algorithm 1 描述）
1. 初始化：s ← s₀；历史 H ← ∅；检查点 K ← [s₀]；所选技能 ← ⊥。
2. 在预算允许内循环：优化器输出一个动作 → 运行器验证合法性 → 执行动作（REVISE / SELECT / STOP / INSPECT / RUNTARGET）→ 记录结果和成本 → 更新资源计数。
3. 返回最终选定技能（若未选择则返回当前技能），在封存测试集上评估一次。

## 6. 论文的主要结论与发现

1. **前沿优化器无需预设流水线也能实现竞争性自我进化**：
   - OEO 在 8 个 SKILLOPT 对比设置中取得 7 胜 1 平；在 6 个 GEPA 确认设置中取得 5 胜（GEPA 的唯一领先为 0.21 个百分点）。
   - OEO 在所有 8 个设置中均超过初始技能；SKILLOPT 改进 7 个；GEPA 改进 5/6 个。
   - 该结论不依赖某个特定流水线设计——SKILLOPT 与 GEPA 具有不同的编辑空间和搜索拓扑，OEO 对两者均具有竞争力。

2. **资源效率**：OEO 中位仅使用 SKILLOPT 配置的 target-interaction token 预算的 34.3%，且在每个设置中都低于该预算——强劲结果不是靠消耗更多交互 token 获得。

3. **静态先验不能解释结果**：单次零交互 GPT-5.5 重写在 4 个测试设置中均未达到 OEO 水平；LiveMath 上静态重写反而降低初始分数，而 OEO 提升 29.84–34.68 个百分点。

4. **委派存在能力边界**：
   - 中等优化器（Qwen3.5-27B）下，SKILLOPT 在 LiveMath 上领先 9.68 pp、在 SearchQA 上领先 3.50 pp。
   - 弱优化器（Qwen3.5-4B）无法通过 OEO 接口产生可执行动作；SKILLOPT 虽可运行，但未能超过初始技能。
   - 能力从中等提升到前沿时，OEO 收益幅度（16.13–7.07 pp）远大于 SKILLOPT（2.42–0.64 pp）——能力越高，委派带来的收益越大。

5. **预设改变的是路径，而非最终行为**：
   - 在 8 个 OEO–SKILLOPT 对中，OEO 的最大编辑量、段落覆盖广度、修订来回率在全部设置中均大于 SKILLOPT。
   - 但 7/8 设置的 pass/fail 一致性 ≥ 0.78，5/8 的 correct-set Jaccard > 0.70。
   - 不同文本路径可以到达重叠的实例级行为；最终文本距离与行为距离的 Spearman 相关仅为 ρ = 0.3095。

6. **总体原则**：预设流水线应视为**能力依赖的脚手架**，而非自进化系统的默认组件。框架应继续掌控目标、权限、预算与评估；当优化器足够强大且反馈可测量时，应将任务特定路线委派给模型本身。

## 7. 优点

- **概念创新**：明确区分“外部治理的优化契约”与“任务特定的优化元策略”，为自进化智能体的设计提供了清晰的分析框架，超越了单纯的提示词比较。
- **消融设计严谨**：通过三组互补实验（零交互对照、能力梯度、全轨迹仪器化分析）系统排除了多种替代解释（先验、优化器无关、资源消耗差异）。
- **双对照组设计**：同时纳入流水线中心（SKILLOPT）和搜索中心（GEPA）两种结构不同的预设方法，使得结论不是针对某一种流水线的偶然结果。
- **过程与结果的双重评估**：不仅比较分数，还比较了提交轨迹（最大编辑、段落覆盖、修订来回率）和实例级行为重叠（pass/fail 一致性、Jaccard 系数），揭示了“路径差异”与“行为差异”的分离。
- **资源使用的精细核算**：分别记录优化器 token 和目标交互 token，区分不同资源瓶颈；不追求等成本匹配，而是分别报告性能与成本，更真实反映实际使用情况。
- **结果可靠性**：所有方法共享同一封存测试集、同一初始技能、同一数据快照和同一评估器，测试集只在优化结束后评估一次。

## 8. 不足与局限

- **基准覆盖面有限**：四个基准（SearchQA、SpreadsheetBench、OfficeQA、LiveMath）虽覆盖不同任务类型，但都属于自然语言 / 问答 / 工具操作/表格处理范畴，未涉及多模态、具身、代码生成或交互环境的长期收益等问题。
- **能力梯度实验较窄**：仅 2 个任务 × 1 个目标模型，中等优化器仅 1 个（Qwen3.5-27B），“能力边界”的准确位置尚不清晰。
- **优化器种类有限**：仅测试了 GPT-5.5、Qwen3.5-27B、Qwen3.5-4B 三个模型；其他系列（Claude、Gemini、Llama 等）尚未覆盖。
- **GEPA 对比的非完全对齐**：SpreadsheetBench 两个 GEPA 细胞是后验匹配检查点而非原生全预算结果，削弱了该组对比的完整性；GEPA 的轨迹不可仪器化，缺少与 OEO 的过程级对比。
- **主指标单一**：主要依赖 pass rate（通过率），未采用部分得分、脚本可验证的中间步骤或人工评估。
- **超时处理不透明**：LiveMath 中存在 item 级超时计为失败的细节，但对其他基准的超时或异常情况的说明不足。
