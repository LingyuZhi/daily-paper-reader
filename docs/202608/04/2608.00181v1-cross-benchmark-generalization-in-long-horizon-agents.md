## 摘要
对于自包含环境中的强化学习（RL），策略可以通过利用环境特有的规律性（工具模式、评分器解析、任务模板）来获得奖励，而非通过获取可迁移的技能，并且分布内保留集共享这些规律性。我们认为，具有判别性的问题是行为层面的，即训练后的智能体如何行动，而跨基准迁移正是寻找该问题答案的合适场所。我们在363个跨27个类别的长时程模型上下文协议（MCP）任务上，使用两阶段SFT-然后-RL流程，对开放权重混合专家模型（Qwen3.5-122B-A10B）进行后训练。Toolathlon性能影响了初始基础模型家族和SFT教师的选择，但没有任何外部基准任务或评分器进入训练，也没有任何外部分数用于奖励、训练超参数、训练检查点选择或停止。在贪心pass@1下，训练后的模型在五项报告的外部评估中均优于基础模型：Toolathlon（+9.6个百分点）、τ^2-Bench（+5.3个百分点）、BFCL-V4（+3.5个百分点）、SWE-Bench Pro（+5.8个百分点）和Terminal-Bench 2（+2.8个百分点）。尽管训练集不包含软件工程任务，但两个软件工程基准均有所提升。一项探索性的配对轨迹分析识别出四种反复出现的行为差异（更谨慎的局部目标形成、构建与目标相关的工作状态、通过局部修复保持父目标稳定、以及验证完成），这些差异在办公工作流和代码中呈现出类似的形式。这些结果提供了描述性证据，表明长时程多工具后训练可以改变工作方式，并迁移到训练领域之外。

## Abstract
For reinforcement learning (RL) in self-contained environments, a policy can get rewards by exploiting environment-specific regularities (tool schemas, grader parsing, task templates) rather than by acquiring transferable skill, and an in-distribution holdout shares those regularities. We argue that the discriminating question is behavioral, namely how a trained agent acts, and that cross-benchmark transfer is the right place to look for it. We post-train an open-weight mixture-of-experts model (Qwen3.5-122B-A10B) on 363 long-horizon Model Context Protocol (MCP) tasks across 27 categories, using a two-stage SFT-then-RL pipeline. Toolathlon performance informed the initial base-family and SFT-teacher choices, but no external-benchmark task or grader entered training and no external score informed the reward, training hyperparameters, trained-checkpoint selection, or stopping. At greedy pass@1, the trained model improves over the base on five reported external evaluations: Toolathlon (+9.6 pp), $τ^2$-Bench (+5.3 pp), BFCL-V4 (+3.5 pp), SWE-Bench Pro (+5.8 pp), and Terminal-Bench 2 (+2.8 pp). Both software-engineering benchmarks improve despite the training collection containing no software-engineering tasks. An exploratory paired-trajectory analysis identifies four recurring behavioral differences (more careful local-goal formation, building goal-relevant working state, keeping parent goals stable through local repairs, and verifying completion) that appear in analogous forms across office workflows and code. These results provide descriptive evidence that long-horizon multi-tool post-training can change ways of working that transfer beyond its training domain.

# 论文详细总结

## 1. 核心问题与整体含义（研究动机与背景）

- **核心问题**：在自包含环境中进行强化学习（RL）时，智能体可能通过利用环境特有的规律性（如工具模式、评分器解析方式、任务模板）而非真正的可迁移技能来获得高奖励。标准的分布内保留集（holdout）由于与训练集共享这些环境自由度，无法排除这种“作弊”可能性。
- **研究立场**：作者认为，判别智能体是否学到可迁移能力的关键在于**行为层面**——即智能体“如何”行动，而非仅仅是“取得了什么成绩”。跨基准迁移是考察这一点的最合适场所。
- **整体含义**：如果后训练带来的行为改变（如更仔细地设定目标、构建工作状态、保持父目标稳定、验证完成度）能跨领域复现，就能提供描述性证据，说明长时程多工具后训练可以产生超越训练领域的可迁移工作方式，而不仅仅是环境特定的过拟合。

## 2. 提出的方法论

- **总体框架**：采用“SFT + RL”两阶段后训练，在自主构建的长时程多工具智能体任务集（LHMTA）上训练，然后在完全外部的基准上评估。
- **训练环境 LHMTA**：
  - 363个训练任务，覆盖27类真实专业工作流（办公套件、终端、日历、文件系统、浏览器等）。
  - 不含软件工程任务。
  - 每个环境通过 MCP 服务器暴露，单条轨迹通常组合多个服务器；成功轨迹平均需 30–40 轮工具调用、8 万–10 万 token。
  - 每个任务有确定性 Python 评分器，按多个判据（criteria）打分。
- **SFT 阶段**：
  - 基础模型：Qwen3.5-122B-A10B（开放权重 MoE，约10B激活参数）。
  - 教师模型：Kimi K2.6，生成仅限 LHMTA 训练任务的轨迹，保留奖励 >0.9 的 3,000 条轨迹。
  - 采用 LoRA（rank=32，α=32）适配所有注意力与 MLP 投影，目的是减少遗忘并降低算力需求。
- **RL 阶段**：
  - 使用序列级 GSPO（Group Sequence Policy Optimization）估计器，避免学习价值模型。
  - 奖励设计：稀疏的 pass/fail + 稠密的判据完成率奖励（rg∈[0,1]）。
  - 对 rg < 0.5 的低分轨迹加入“努力下限” e = min(0.30, 0.05·min(工具调用数, 6)) + 0.05·正常完成 + 0.05·使用≥3种不同工具；最终奖励取 max(rg, e)，下限最高0.40，作为低分时的保护，而非成功奖励的附加。
  - 取消了早先的逐前缀奖励实现，因为策略会优化受奖励前缀而非完整完成。
  - 稳定性处理：将大型工具输出写入文件供 grep；压缩循环修正序列；保留最近推理轨迹以减少上下文膨胀。
- **外部评估防火墙**：
  - 不把任何外部基准任务或评分器纳入训练。
  - 除最初的基础模型家族和 SFT 教师选择外，所有外部基准分数均未用于奖励设计、超参数选择、检查点选择或停止条件。
  - 评估统一使用各基准的原生评分协议，贪心解码（greedy pass@1）为主。

## 3. 实验设计

- **训练数据**：LHMTA 363 个训练任务 + 40 个分布内保留任务（用于管道检查，不参与训练）；另有 27 个任务因依赖限流 API 或无法确定性运行被排除。
- **外部评估基准（5个）**：
  - Toolathlon（长时程工具执行）
  - τ²-Bench（对话式双控制环境，含航空/零售/电信/银行）
  - BFCL-V4（函数调用/智能体评估）
  - SWE-Bench Pro（仓库级软件工程问题）
  - Terminal-Bench 2（命令行环境困难任务）
- **对比方法**：无额外基线模型对比；主要对比是“基础模型 vs 训练后模型”（同一模型训练前后），在相同评估协议下进行。
- **行为分析实验**：
  - 配对轨迹分析：对同一任务、同一提示、同一环境脚手架下基础模型和训练后模型的轨迹进行成对比较，聚焦“失败→成功”的翻转案例；使用 Claude Opus 4.8 自动化根因分析，再由作者人工验证。
  - 在 SWE-Bench Pro 上统计了 731 对匹配任务对，量化检索调用次数、重复检索信息比例、参考补丁文件重叠数、新增行数、运行中是否包含正式测试等指标。
- **补充诊断**：Toolathlon 分类别（Academia, Campus, Daily, Finance, Office, Shopping, Tech）表现；BFCL 子切片（Agentic, Multi-Turn, Live 等）表现；四样本温度1.0诊断（来自早期快照，与更新的贪心结果分开报告）。

## 4. 资源与算力

- **训练设备**：8 个 actor 节点 × 8 张 H200 GPU（即 64 张 H200）。
- **训练基础设施**：基于 slime、Megatron-LM、SGLang；SFT 框架为 ms-swift；推理与评估使用 SGLang（BF16）。
- **训练配置**：SFT 最大长度 131,072，1 epoch；RL 最大序列长度 80K，每提示 8 个样本，rollout 温度 1.0，学习率 5×10⁻⁵，KL 系数为 0（KL-loss 系数 0.001），熵系数 0.001。
- **训练时长**：论文未明确给出 SFT 和 RL 的具体训练时长；仅说明长轨迹使 RL 运行计算密集（上下文并行分片开销大）。扩展训练到第 2、3 epoch 会导致退化，因此只采用单 epoch 输出。

## 5. 实验数量与充分性

- **主要实验**：一次完整的 SFT+RL 后训练，五个外部基准 + 一个保留集评估（贪心 pass@1）。
- **诊断实验**：四样本温度1.0的早期快照（作为“原生诊断”，不做统计推断）；Toolathlon 分类别表现；BFCL 切片表现；SWE-Bench Pro 行为量化指标（731对）。
- **消融实验**：未进行无努力下限的消融，也未做 SFT-only 或 RL-only 的归因消融；作者明确说明实验并非设计用于将迁移归因于某一单独阶段。
- **统计充分性**：作者承认单次训练运行无法估计训练随机性方差；基准之间相互关联且使用原生加权聚合，因此没有进行正式跨基准假设检验；所有结果均作为描述性点估计。基于此，实验能支持“方向性提升”的描述性结论，但不能证明统计显著性。

## 6. 主要结论与发现

- **跨基准普遍提升**（贪心 pass@1，基础→训练后）：
  - LHMTA 保留集：+17.5 pp（10.0→27.5）
  - Toolathlon：+9.6 pp（22.2→31.8）
  - τ²-Bench：+5.3 pp（54.8→60.1，保留快照）
  - BFCL-V4：+3.5 pp（55.7→59.2）
  - SWE-Bench Pro：+5.8 pp（20.5→26.3）
  - Terminal-Bench 2：+2.8 pp（44.9→47.7）
- **关键发现**：训练集不含任何软件工程任务，但两个软件工程基准仍获得提升，这是最强的跨域迁移信号。
- **行为变化**：四类反复出现的行为差异，且在办公工作流和代码任务中呈现类似形式：
  1. 更谨慎的局部目标形成（基于实际环境状态定义子目标，而非表面理解）；
  2. 构建与目标相关的工作状态（利用环境结构/缓存/已有工具，而非重新实现或忽略关键信息）；
  3. 保持父目标稳定（在修复局部问题时不被陈旧测试或中间错误带偏）；
  4. 基于证据的完成验证（验证下游真正依赖的属性，而非自我参照或代理指标）。
- **量化支持**：SWE-Bench Pro 上训练后模型重复检索信息减少（22.5%→14.3%）、参考补丁文件重叠增大（2.69→3.08）、新增行数大幅减少（415.5→111.7）、包含正式测试的轨迹比例从37.5%升至73.3%。

## 7. 优点

- **评估立场严谨**：明确区分“分布内保留集”和“外部基准”，设置外部评估防火墙，避免外部结果污染训练决策；报告方式透明，分开不同来源的数据（更新后贪心 vs 早期快照诊断）。
- **行为导向的解释**：不止报告分数，而是通过配对轨迹分析揭示“如何”发生变化，组织成四类可操作的行为模式，并附有具体事例和量化指标，为理解迁移机制提供更深的视角。
- **跨领域测试设计**：在包含软件工程的外部基准上测试，即便训练域刻意不含该类任务，增强了迁移结论的可信度。
- **坦诚的局限披露**：主动说明单次运行、无统计显著性、基准相关性、已知 Toolathlon 表面重叠、能力-倾向的混淆等问题，符合可复现性要求。
- **对数据设计的启发**：提出“任务压力”（task pressure）概念，将数据多样性从表面多样性转向底层推理压力，为后续数据建设提供了实践方向。

## 8. 不足与局限

- **单次运行与统计推断缺失**：只运行了一次完整后训练，未估计训练随机性方差；没有正式置信区间或显著性检验，只能做描述性结论。
- **无法归因阶段**：SFT 和 RL 是一体化流程，无法区分是 SFT、RL 还是两者交互带来了迁移。
- **缺少关键消融**：未做“无努力下限”的消融，无法排除部分提升源于直接塑造的“尝试完成任务”行为的替代解释。
- **基准污染风险**：Toolathlon 与训练集共享 MCP 服务器和工具 schema 实现，且 Toolathlon 排行榜分数影响了基座选择和教师选择；尽管任务与评分器未进入训练，但仍存在表面重叠。基础模型预训练语料无法审计，外部基准可能在预训练中已见过。
- **行为分析的主观性**：行为分类是基于自动根因分析 + 人工检查的迭代框架，标签并非互斥，也不是机制层面的证明；量化指标（如参考补丁文件数、新增行数）是相关证据而非因果证据。
- **外部泛化证据有限**：五个基准之间的相关性已知，且 Termial-Bench 与 SWE-Bench Pro 使用同一套保留快照（τ2-Bench 来自快照），一致性被强调为描述性而非检验性。
- **任务覆盖偏差**：训练任务由“能够产生有意义失败”的哲学筛选，排除了依赖外部 API 的任务，可能限制了对某些真实场景的泛化。
