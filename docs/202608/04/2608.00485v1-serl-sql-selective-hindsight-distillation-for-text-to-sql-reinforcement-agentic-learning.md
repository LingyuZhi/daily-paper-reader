## 摘要
近期文本到SQL系统越来越依赖于多轮交互、执行反馈和强化学习。然而，大多数现有方法仅将执行正确性用作轨迹级奖励，这为识别导致成功或失败的SQL决策提供的指导有限。我们提出了SERL-SQL，一种用于多轮文本到SQL智能体的选择性执行接地强化学习框架。SERL-SQL采样在策略SQL交互轨迹，并使用仅训练使用的教师模型通过执行反馈重新评分学生的动作。由此产生的师生似然差距被转换为有界、掩蔽权重，仅在SQL和工具动作token上重新加权GRPO优势。这样，任务奖励保留了优化方向，而执行后见之明提供了局部信用分配。在BIRD、Spider和跨域基准上的实验表明，SERL-SQL取得了有竞争力的性能，在BIRD-Dev上达到76.56%的执行准确率，在Spider-Test上达到89.92%。此外，我们基于奖励的选择策略紧密接近oracle Best-of-N上界，并且始终优于基于一致性的选择，表明SERL-SQL生成了高质量候选，这些候选可以通过轻量级执行接地奖励可靠地识别。我们的代码将在https://github.com/Ffunkytao/SERL-SQL发布。

## Abstract
Recent Text-to-SQL systems increasingly rely on multi-turn interaction, execution feedback, and reinforcement learning. However, most existing methods use execution correctness only as a trajectory-level reward, which provides limited guidance for identifying the SQL decisions responsible for success or failure. We propose SERL-SQL, a selective execution-grounded reinforcement learning framework for multi-turn Text-to-SQL agents. SERL-SQL samples on-policy SQL interaction trajectories and uses a training-only teacher to re-score student actions with execution feedback. The resulting teacher--student likelihood gap is converted into bounded, masked weights that reweight GRPO advantages only on SQL and tool-action tokens. In this way, task rewards preserve the optimization direction, while execution hindsight provides localized credit assignment. Experiments on BIRD, Spider, and cross-domain benchmarks show that SERL-SQL achieves competitive performance, reaching 76.56% execution accuracy on BIRD-Dev and 89.92% on Spider-Test. Moreover, our reward-based selection strategy closely approaches the oracle Best-of-N upper bound and consistently outperforms consistency-based selection, showing that SERL-SQL produces high-quality candidates that can be reliably identified by lightweight execution-grounded rewards. Our code will be released at https://github.com/Ffunkytao/SERL-SQL.

## 1. 核心问题与总体含义

### 研究背景与动机

- **Text-to-SQL 任务的发展趋势**：从早期单次生成 SQL 转向多轮交互的智能体（Agentic）模式，模型需要经历 schema 选择、SQL 生成、执行、验证、修正等多个环节。
- **现有方法的核心缺陷**：大多数方法（如 GRPO 等强化学习框架）只把“执行正确性”作为**轨迹级（trajectory-level）奖励**，即整条交互轨迹共享同一个奖励信号。这种粗粒度反馈无法定位具体是**哪一个 SQL 决策**导致了成功或失败，导致信用分配（credit assignment）模糊——推理 token、SQL token、格式 token 被同等地更新或抑制。
- **论文的核心见解**：执行反馈不应仅作为最终结果奖励，更应作为**训练阶段的后见之明（hindsight）**，为可执行的 SQL 决策提供局部化、精细化的信用信号。

### 论文定位

- 提出了 **SERL-SQL**（Selective Execution-grounded Reinforcement Learning for Text-to-SQL），一个选择性执行接地强化学习框架。
- 核心思想：在训练时引入一个**仅训练阶段可用的教师模型**，利用数据库执行反馈对学生的 on-policy 动作进行重打分，将师生似然差转化为有界掩码权重，仅对 SQL 和工具动作 token 的 GRPO 优势进行重加权——**任务奖励决定优化方向，执行后见之明决定更新幅度与局部性**。

## 2. 方法论：核心思想与关键技术细节

### 2.1 整体架构（四阶段流程）

| 阶段 | 功能 |
|------|------|
| **Stage 1：Schema Grounding** | 离线构建列感知向量索引，在线通过关键词/实体检索数据库值，结合推理式与基于值的 schema 链接，产出紧凑的 grounded schema S′ |
| **Stage 2：多轮 SQL Agent Rollout** | 学生策略 π<sub>θ</sub> 通过 think→act→observe 循环，迭代生成 SQL、执行、观察反馈、修正；采用层级式奖励验证器给轨迹打分 |
| **Stage 3：选择性执行后见之明教师** | 训练专用教师 π<sub>T</sub> 在**执行反馈上下文中**重评学生的 on-policy token，计算师生对数似然差 |
| **Stage 4：后见之明引导的优势重加权** | 将似然差转为有界、符号感知的权重，通过动作掩码仅应用于 SQL/工具动作 token，最终更新策略 |

### 2.2 关键技术细节

**轨迹定义与奖励**：
- 轨迹 τ = (s₀, a₀, o₀, ..., s_T, a_T, o_T)，其中 a_t 包含推理片段和 SQL/工具动作。
- 轨迹级奖励为稀疏三层结构：+1（有效且正确）、0（有效但错误）、−1（无效格式）。

**GRPO 基准**：
- 标准 GRPO 将轨迹级优势 Aⁿ 分配给所有 token，公式：Aⁿ = (Rⁿ − mean(R)) / (std(R) + ε_A)
- 优化目标：L_GRPO(θ) = −E_τ[Σ_{t,i} ℓ_GRPO(θ; Aⁿ)] + β·KL(π_θ ∥ π_ref)

**师生差距计算**：
- 教师条件化在执行后见之明 c<sub>t</sub><sup>ex</sup> 上：log π_T(y_{t,i} | h_t, y_{t,<i}, c<sub>t</sub><sup>ex</sup>)
- 学生仅依赖动作前可用信息：log π_θ(y_{t,i} | h_t, y_{t,<i})
- 差距：Δ_{t,i} = log π_T − log π_θ

**符号感知有界权重**：
- w_{t,i} = clip(exp(sgn(Aⁿ)·sg[Δ_{t,i}]), w_min, w_max)，其中 w_min = 1 − ε_w，w_max = 1 + ε_w
- 即：正优势轨迹中，被执行反馈“支持”的 token 获得更强强化；负优势轨迹中，被反馈“否定”的 token 受到更强抑制。

**选择性动作掩码**：
- m_{t,i} ∈ {0,1}，仅对可执行 SQL 和工具动作 token 为 1。
- 有效权重：w̄_{t,i} = (1 − m_{t,i}) + m_{t,i}·w_{t,i}——非动作 token 保持原始 GRPO 权重。

**后见之明衰减系数**：
- 引入 α<sub>k</sub> ∈ [0,1] 随训练步数衰减，最终 token 级优势：Ã_{t,i} = Aⁿ[(1 − α_k) + α_k·w̄_{t,i}]
- 早期训练利用执行后见改善信用分配，后期逐渐回归纯奖励驱动的 GRPO 目标。

**推理阶段**：教师被完全移除，学生策略独立作为多轮 SQL 智能体运行，不影响部署复杂度。

## 6. 主要结论与发现

1. **执行后见之明能有效改善信用分配**：相比轨迹级 GRPO，增加执行反馈的局部重加权在 BIRD-Dev 上提升了约 3 个百分点（71.94 → 74.95，14B 消融对比），说明因果对齐的 token 级信号确实有帮助。
2. **奖励型选择策略接近 oracle 上界**：reward_max 在 16 条采样轨迹下紧密逼近 Best-of-N oracle 性能，并**显著优于一致性（majority-vote）选择**——表明 SERL-SQL 策略生成的高质量候选比“多数一致”更具可识别性。
3. **反馈的“局部性”比“丰富性”更重要**：立即观察（Immediate Observation）效果最佳（75.52/89.92/81.68），完整观察反而下降，说明过长/过度冗余的后见信息会模糊 token 级归因。
4. **Schema grounding 是最大性能杠杆**：去掉 schema grounding 导致最大跌幅（−8.53%），说明紧凑和语义对齐的 schema 上下文是有效信用分配的前提。
5. **剩余错误主要来自 join 构建（29.1%）与语义误解（24.6%）**，单纯提高 SQL 可执行性不足以解决深层多表推理问题。
6. **训练步数与选择效果存在权衡**：训练中后期策略变强但采样多样性可能下降，影响多轨迹选择的提升空间。

## 7. 方法优点（续）

- **设计新颖且优雅**：将“执行反馈”从结果奖励重新定位为“训练阶段的后见之明”，这一视角转换避免了在推理时引入额外开销，同时保留了执行信号的全部细化价值——哲学上类似于 DAgger 式的「让教师引导探索，但让学生独立部署」的思路。
- **理论上有界、实践上安全**：权重被裁剪在 [1−ε_w, 1+ε_w] 内，且通过符号感知机制与 GRPO 的优势方向严格对齐——不会出现奖励 hacking 或权重爆炸问题；同时教师的输出经过 stop-gradient，避免了师生共训中的非平稳目标问题。
- **引入渐退（decay）机制很务实**：从“执行反馈主导”平滑过渡到“奖励驱动”，兼顾了训练早期的信用分配需求与训练后期的策略稳定性，这是纯 GRPO 或纯执行加权方法都没有的调和方案。
- **选择性动作掩码具有可移植性**：思路不绑定于特定 SQL 智能体框架，只要策略输出中包含可区分的“可执行动作 token”，即可套用到其他代码生成/工具调用场景。
- **实验规模完整且有说服力**：在 7B/14B/32B 三个规模上验证了方法的稳定性；在 BIRD 单数据集上训练却在四个跨域基准上评测，展示了较强的泛化能力。

## 8. 方法缺点与潜在局限

### 8.1 方法论层面

- **依赖一个“更好的教师”这一前提**：论文隐含假设教师 π_T 在获得执行反馈后一定比学生 π_θ 产生更可靠的条件分布。但教师本身也是训练中的模型，如果教师在早期阶段质量不足，其提供的“后见之明”可能传导错误信号，而论文对教师质量的控制与监控手段着墨不多。
- **执行反馈的时间错位问题未完全解决**：token 级权重 w_{t,i} 是在整条轨迹产生后才利用最终执行结果计算的，但决策 t 时刻的“因果正确性”未必与最终结果一致——例如一条最终成功的轨迹中，中间某次 SQL 可能是低质量的，而最终错误轨迹中的某些早期决策可能是完全正确且被后期错误“连累”的。批归一化式的符号对齐只能部分缓解这种因果混淆，无法从根本上进行真正的**per-step credit assignment**。
- **训练代价显著高于普通 GRPO**：需同时运行学生和教师两个模型的前向传播，且教师需看到执行反馈后的完整上下文，内存占用与计算量几乎翻倍；论文未给出与纯 GRPO 训练成本的定量对比。
- **后见之明衰减的调度策略缺乏理论保障**：α_k 的衰减曲线、衰减速率如何选择，论文没有给出敏感性分析或自适应方案，更像手工设定的工程细节。

### 8.2 实验与泛化层面

- **训练数据单一**：只在 BIRD 上训练，未报告“在 Spider 上训练→在 Spider-Test 上测试”的同类设置，因此 Spider-Test 89.92% 的领先是否能归因于方法本身，还是因为 BIRD 训练集更接近真实场景而带来迁移优势，无法完全判定。
- **与同基座模型的直接对比缺失**：未在 Qwen2.5-Coder-Instruct 基座下与其他 RL 方法（如 SQL-R1、PaVeRL-SQL 在同一基座上的版本）进行严格对齐实验，公平性受限于公开榜单的差异。
- **推理代价未报告**：多轮 agent 迭代 + schema grounding 检索在实际推理时的延迟、token 消耗与成本没有量化，而这一部分是实际部署中最关键的因素之一。
- **32B 规模在 BIRD-Dev 上低于 7B 基线**：论文以“跨域更强”作解释，但未深入分析为什么 BIRD 这一训练分布内基准上模型规模增大反而没有带来收益——疑似与更大模型在训练后期过拟合 BIRD 分布或采样多样性下降有关，但这只是推测，论文并未给出证据。

## 9. 未来研究方向

- **真正的逐步因果奖励**：引入每个 RL 步的中间验证器（如子目标达成度、中间结果表的匹配度），使执行反馈在**决策发生时**即时给出，而非事后回溯，有望进一步细化信用分配。
- **更高效的师生共训架构**：探索教师参数共享、蒸馏式教师或间歇式教师更新（如每 N 步同步一次），以降低训练开销。
- **扩展到更多代码生成任务**：SERL-SQL 的框架并不限于 SQL，可尝试迁移到 Python 代码生成、API 调用规划、Bash 工具使用等同样具备“执行反馈”信号的智能体场景。
- **自适应衰减与权重的学习化**：用元学习或上下文 bandit 自动学习 α_k 与 ε_w，替代目前的手工衰减曲线。
- **更大规模与更多训练数据的验证**：在 Spider、Spicier、KaggleDBQA 等多数据源联合训练，以及在 70B+ 规模模型上验证方法有效性。

## 10. 总体评价

| 维度 | 评分（满分 5） | 备注 |
|------|--------------|------|
| 问题重要性 | ⭐⭐⭐⭐⭐ | 信用分配是 Text-to-SQL RL 的核心痛点 |
| 方法新颖性 | ⭐⭐⭐⭐ | 执行后见之明概念此前在 LLM 推理/代码生成中已有雏形，但将其与 GRPO、动作掩码、衰减退化的组合应用是原创的 |
| 理论严密性 | ⭐⭐⭐ | 缺乏严格的收敛性分析，设计决策多为启发式；但有界性设计值得肯定 |
| 实验充分性 | ⭐⭐⭐⭐ | 消融、基线、跨域评测丰富，但训练设置单一、与同基座对齐不足 |
| 工程实用性 | ⭐⭐⭐⭐ | 推理阶段零额外开销，实现复杂度可控，但训练成本高 |
| 论文写作质量 | ⭐⭐⭐⭐ | 结构清晰、图表直观；部分细节依赖附录 |

**一句话总结**：SERL-SQL 通过引入一个仅在训练时使用、以执行反馈为条件的「后见之明教师」，将粗粒度的轨迹级 GRPO 优势细化为 SQL/工具动作 token 上的符号感知、有界、可衰减的加权信号，在几乎不增加推理开销的前提下，显著改善了多轮 Text-to-SQL 智能体的信用分配质量，并在多基准上取得了有竞争力的表现；其核心思想虽简洁，但工程设计与实验验证都相当扎实，是强化学习与执行反馈结合方向上的一篇高质量工作。
