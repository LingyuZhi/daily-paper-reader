## 摘要
现有的搜索增强型LLM智能体使用强化学习进行训练以提升其推理能力。然而，这些方法主要依赖于结果级别的奖励，这几乎不提供对搜索行为的监督，并且忽视了智能体正确分解复杂查询的能力。为了解决这个问题，我们提出了PROGRESS，它利用教师引导的覆盖率奖励来明确塑造策略模型的分解查询生成。在训练期间，冻结的教师模型被用来将复杂查询分解为必要的搜索查询。这些必要的搜索查询被用来引导策略模型的搜索行为。我们的方法集成到R1风格的训练框架中，在不进行密集过程级监督的情况下，为查询分解决策提供轻量级指导。实验表明，覆盖率引导的强化学习提高了整体任务性能，突出了在智能体LLM中显式监督搜索策略的重要性。

## Abstract
Existing search-augmented LLM agents are trained using Reinforcement Learning to boost its reasoning capabilities. However, these approaches primarily rely on outcome-level rewards, which provide little supervision over search behavior and overlook agent's ability to decompose complex queries properly. To mitigate this issue, we propose PROGRESS which utilizes teacher-guided coverage reward to explicitly shape decomposed query generation of the policy model. During training, frozen teacher models are used to decompose complex queries into essential search queries. These essential search queries are utilized to guide the search behavior of the policy model. Integrated into an R1-style training framework, our approach provides lightweight guidance over query decomposition decisions without dense process-level supervision. Experiments show that coverage-guided RL improves overall task performance, highlighting the importance of explicitly supervising search strategies in agentic LLMs.

## 1. 论文的核心问题与整体含义（研究动机和背景）

- **背景**：大语言模型（LLM）结合外部搜索工具可以执行复杂多跳推理任务。在此类智能体（agent）场景中，模型不仅需要学会基于检索证据进行推理，还需要学会"搜索什么"和"何时搜索"。近期研究（如 Search-R1）表明，用强化学习（RL）训练小型 LLM 在推理与搜索动作之间交替，可显著提升多跳问答及知识密集型任务的表现。
- **核心问题**：现有的 RL 训练搜索智能体方法主要依赖**结果级奖励**（如精确匹配准确率），存在三大局限：
  1. 对搜索行为几乎没有直接监督，无法指导中间搜索质量；
  2. 忽视了智能体正确分解复杂查询的能力；
  3. 容易导致低效搜索行为、生成复合搜索查询（而非原子化的细粒度查询），以及小模型对推理模式的"死记硬背"。
- **本文含义**：成功进行多跳推理的关键在于**将复杂查询分解为覆盖必要信息需求的子查询**，并提出 PROGRESS 框架，通过显式监督查询分解质量来弥补上述不足，从而在不依赖密集过程级人工标注的前提下，提升搜索增强 LLM 智能体的整体任务性能。

## 2. 论文提出的方法论

### 2.1 核心思想
利用**冻结的教师模型**（Qwen2.5-72B-Instruct）将复杂查询离线分解为一组"关键搜索查询"，将其作为弱监督信号，通过计算策略模型生成的搜索查询与教师关键查询之间的**覆盖率奖励**（coverage reward），显式引导策略模型的查询分解行为。

### 2.2 关键技术细节

**（1）搜索增强 LLM 智能体的 RL 框架**
- 智能体生成的轨迹包含多轮检索与推理：`<search>` 触发搜索、`<information>` 包裹检索内容、`<think>` 包裹推理步骤、`<answer>` 包裹最终答案。
- 训练目标为最大化期望奖励同时约束与参考策略的 KL 散度：
  \[
  \max_\theta \mathbb{E}_{x\sim D, y\sim\pi_\theta(\cdot|x;\mathcal{R})}[r(x,y)] - \beta D_{KL}(\pi_\theta \| \pi_{ref})
  \]
- 使用 **PPO（近端策略优化）** 作为优化算法，仅对策略生成的 token 进行优化。

**（2）覆盖率奖励（Coverage Reward）计算流程**
- **教师查询生成**：对每个输入问题 x，冻结教师模型生成关键搜索查询集合 \(Q_T(x) = \{q_1^T, ..., q_K^T\}\)；
- **策略查询提取**：从策略模型生成的轨迹 y 中提取搜索查询集合 \(Q_P(x,y) = \{q_1^P, ..., q_M^P\}\)；
- **查询匹配**：利用 LLM judge（Qwen2.5-72B-Instruct）基于**语义一致性**和**粒度一致性**两个标准，识别匹配查询集合 \(I(x,y) = Q_P(x,y) \cap Q_T(x)\)；
- **精确率与召回率**：
  - Precision = |I| / |Q_P|：衡量策略查询与相关信息需求的匹配程度，惩罚冗余/无关搜索；
  - Recall = |I| / |Q_T|：衡量策略查询对教师识别出的子问题的覆盖程度；
- **覆盖率奖励**：以精确率和召回率的**调和平均（F1-score）**作为最终信号：
  \[
  r_{cov}(x,y) = \frac{2 \times Precision \times Recall}{Precision + Recall}
  \]
  F1 形式同时兼顾完整性与聚焦性，鼓励模型生成"简洁但全面"的查询分解。

**（3）总奖励函数**整合结果奖励、格式奖励与覆盖率奖励：
\[
r(x,y) = r_{ans}(x,y) + r_{format}(y) + \lambda_{cov} r_{cov}(x,y)
\]
其中 \(r_{ans}\) 为精确匹配奖励，\(r_{format}\) 为格式奖励，\(\lambda_{cov}\) 为覆盖率奖励权重（实验中设为 0.2）。

**（4）设计特点**
- 覆盖率奖励是在轨迹级别（trajectory-level）计算的，而非逐步（step-level）的密集过程奖励，在保留自回归生成灵活性的同时引导检索行为；
- 不规定固定的推理轨迹，仅提供高层级的"关键子问题"表示；
- 通过精确率和召回率的联合优化，避免两种退化策略：生成大量松散相关查询，或只覆盖少量关键查询。

## 6. 论文的主要结论与发现

1. **主性能提升**：PROGRESS 在所有多跳 QA 数据集（HotpotQA、2wiki、MuSiQue）上均优于全部基线，其中在 MuSiQue 上比第二名 Search-R1 高出约 5% 绝对 EM 准确率（16.01% vs 13.65%）；综合 6 个数据集的平均值达到 39.72%，胜过所有对比方法；
2. **仅多跳训练效果更佳**：只用 HotpotQA 训练时，PROGRESS 的提升更加明显（平均 31.28% vs Search-R1 的 26.96%），说明覆盖奖励对多跳分解策略的塑造作用显著；
3. **查询质量提升**：在 Completeness（覆盖完备性）和 Granularity（原子粒度）两个维度上，PROGRESS 均显著优于 Search-R1；
4. **检索准确性提升**：PROGRESS 显著提升检索准确率（如 HotpotQA 上 55.54% vs 49.37%），表明更好的查询分解直接改善了检索效果；
5. **模型泛化性**：在 Qwen2.5-1.5B 上也获得了一致改进，验证了方法在不同模型规模上的可迁移性；
6. **通用 QA 保持竞争性**：在通用 QA 数据集上保持竞争力或略有提升，说明覆盖奖励不会损害单跳推理能力。

## 7. 优点

- **轻量级监督**：仅需在训练前用教师模型离线生成一次查询集，无需逐步（step-level）的过程级人工标注，成本可控；
- **新颖的奖励设计**：将覆盖率奖励转化为 F1-score 形式，同时优化精确率和召回率，从机制上避免了"刷大量查询"或"只搜一个查询"的退化策略；
- **与现有框架兼容**：直接集成到 Search-R1 的 RL 训练框架中，保留了检索 token 掩码和 KL 正则化等稳定性机制，便于复现与扩展；
- **实验证据充实**：不仅报告了最终 EM 指标，还从查询质量、检索质量、定性案例、模型规模泛化等多个角度验证方法有效性，论证链条完整；
- **明确的问题定位**：聚焦于"查询分解质量"这一被现有结果级 RL 方法忽视的关键瓶颈，定位清晰且具有实际意义。

## 8. 不足与局限

- **LLM judge 引入额外偏差与成本**：查询匹配依赖 Qwen2.5-72B-Instruct 的语义判断，其本身的不一致性和主观性可能影响奖励准确性；同时每次 rollout 都需调用大模型做匹配，带来额外的计算开销；
- **奖励权重的敏感性未分析**：\(\lambda_{cov}\) 固定为 0.2，未做敏感性分析，在实际应用中可能需要针对不同任务调整；
- **训练-评估跨域偏差**：训练集只包含 NQ 和 HotpotQA，MuSiQue、2wiki、PopQA、TriviaQA 均为跨域评估；虽然这验证了泛化能力，但未测试在更多样化的训练数据组合下的表现；
- **模型规模局限**：仅在 3B 和 1.5B 的小模型上验证，未测试更大规模模型（如 7B/72B）的效果，而大模型本身的查询分解能力可能更强，覆盖奖励的增益可能有所不同；
- **评估指标单一**：主实验仅用 EM 作为最终答案的正确性指标，未使用 F1、ROUGE 等更鲁棒的评价指标；
- **未与过程级奖励方法对比**：上文提到，未与 HiPRAG 等提供过程级奖励的方法进行实验对比，削弱了对"轨迹级覆盖奖励与过程级奖励孰优"这一问题的说服力；
- **量化不确定性缺失**：未报告多次独立运行的标准差，部分性能差异（如 1.5B 模型上 PROGRESS vs Search-R1 的差距）可能未达到统计显著；
- **论文篇幅限制**：全文仅 5 页，许多实现细节（如 PPO 超参数、LLM judge 的 prompting 方式、教师查询的生成方法）未能充分展开。
