## 摘要
大型语言模型（LLM）智能体通常通过修改提示、模型或手写工作流来改进，而模型周围的执行框架被视为固定基础设施。我们认为该框架本身就是一个可学习的控制层。我们将框架操作形式化为一个有限时域的执行框架MDP，其中轻量级控制器选择结构化的执行动作，而LLM执行器保持冻结。控制器使用优势加权回归从离线rollouts中训练，仅依赖终端任务评分奖励。我们还将最终任务质量与事后执行框架成熟度评分分离，该评分衡量框架是否遵循可靠的执行模式，而不仅仅看最终答案是否正确。这种分离为框架学习提供了有限缓冲区的视角：最终质量的提升需要离线缓冲区中的高回报支持，而过程行为可以在其与优势加权动作一致时发生变化。在六个受控域和两个公共基准适配器上，学习到的控制器一致地改善了验证行为，并选择性地提高了最终任务质量，在适配的tau-bench零售、适配的AgentBench DB-Bench以及使用校准的结构化验证器进行编码方面取得了最大改进。与行为克隆和强制检查的消融实验表明，这些改进不能通过模仿或简单添加检查来解释。这些结果将框架控制确定为冻结LLM智能体的可学习层，同时表明当更好的过程控制变为更好的最终答案时，离线支持有限。

## Abstract
Large language model (LLM) agents are usually improved by changing prompts, models, or hand-written workflows, while the execution harness around the model is treated as fixed infrastructure. We argue that this harness is itself a learnable control layer. We formalize harness operation as a finite-horizon Harness MDP, where a lightweight controller selects structural execution actions while the LLM executor remains frozen. The controller is trained from offline rollouts using advantage-weighted regression with only terminal task-rubric rewards. We also separate final task quality from a post-hoc Harness Maturity Score, which measures whether the harness follows reliable execution patterns rather than only whether the final answer is correct. This separation gives a finite-buffer view of harness learning: final-quality gains require high-return support in the offline buffer, while process behavior can shift whenever it aligns with advantage-weighted actions. Across six controlled domains and two public-benchmark adapters, the learned controller consistently improves verification behavior and selectively improves final task quality, with the largest gains on adapted tau-bench retail, adapted AgentBench DB-Bench, and coding with a calibrated structural verifier. Ablations against behavior cloning and Forced CHECK show that the gains are not explained by imitation or by simply adding checks. These results identify harness control as a learnable layer for frozen LLM agents, while showing that offline support limits when better process control becomes better final answers.

## 1. 核心问题与整体含义（研究动机和背景）
- **核心问题**：当前LLM智能体系统通常将执行框架（harness，即决定何时观察环境、检索证据、调用工具、草拟答案、检查、修订、终止等控制逻辑）视为固定基础设施，但作者认为该框架本身是一个可学习的控制层，其决策质量直接影响智能体整体表现。
- **背景**：现有系统大多依赖手动编写的规则、提示模板或多智能体脚手架，这些方式在不同难度、不同阶段的任务中采用固定控制逻辑，容易导致资源浪费或失败。例如，总是检查会浪费预算，总是直接提交则会忽略未验证的草稿。因此，需要学习一个状态依赖的控制策略，以实现更优的执行流程。

## 2. 提出的方法论
- **核心思想**：将执行框架操作形式化为一个有限时域的Harness MDP，其中控制器根据当前轨迹状态选择结构化动作，而底层LLM执行器保持冻结。控制器通过离线强化学习（优势加权回归，Advantage-Weighted Regression, AW）从固定 rollout 缓冲区中学习，仅使用终端任务评分奖励，不更新LLM参数或使用中间奖励。
- **关键技术细节**：
  - **Harness MDP**：状态向量包含轨迹进度、草稿状态、证据覆盖、工具输出、验证器反馈、失败次数、剩余预算等；动作空间为7个结构化原子动作：OBSERVE、RETRIEVE、CALL-TOOL、DRAFT、CHECK、REVISE、SUBMIT。
  - **训练目标**：采用优势加权回归损失函数：
    \[
    L(\theta) = -\mathbb{E}_{(s,a)\sim D}\left[\exp(A(s,a)/\beta) \cdot \log \pi_\theta(a|s)\right]
    \]
    其中 \(A(s,a)\) 为轨迹优势（基于终端评分计算），\(\beta\) 为温度参数。该损失相当于对高优势轨迹中的状态-动作对进行加权行为克隆。
  - **过程与结果分离**：引入事后Harness Maturity Score (HMS)，由7个过程事件（CheckBeforeSubmit, EvidenceBeforeClaim, TestBeforeSubmit, RevisionAfterFailure, ValidToolUse, StopWhenSufficient, EarlySubmit）组成，仅用于评估，不作为训练奖励。
  - **控制器架构**：单隐层MLP（64个隐藏单元），输出7个动作的softmax，无效动作被域适配器屏蔽。训练超参数：Adam学习率 \(10^{-3}\)，batch size 256，20个epoch，\(\beta=0.2\)，权重裁剪到[0.1, 10.0]，熵正则化系数0.01。

- **基准方法**：

## 6. 主要结论与发现
- **过程控制可学习**：在所有8个设置中，AW均显著提升了提交前检查（CheckBeforeSubmit）的比率（从接近0%提升至5.6%~17.8%）。这表明控制器能够从离线缓冲区中学习到可复用的控制习惯。
- **最终质量提升有限但选择性地出现**：最终任务质量的大幅提升仅限于编程（+10.0%）、τ-bench零售适配器（+18.2%）和AgentBench DB-Bench适配器（+13.2%）。其他受控域（知识工作、规划等）增益很小或接近零，甚至略有下降（研究、多工具、长记忆）。
- **过程与结果分离的原因**：理论分析（定理2）表明，过程改进仅需过程统计量与优势权重在缓冲区中正相关（通过协方差），而最终质量改进受限于缓冲区中的最高回报（buffer slack）。因此当缓冲区中存在高回报轨迹时（如零售、DB-Bench、编程），AW能同时提升过程与结果；否则过程可改善但结果未必。
- **消融优于基线**：AW在所有8个设置中均优于BC，在5个设置中优于FC，证明增益来源于学习的条件控制而非简单模仿或强制检查。
