## 摘要
大型语言模型（LLM）如何解决当前无法解决的问题？重复采样扩展了测试时计算量，但GPU成本随尝试次数线性增长，而使用可验证奖励的强化学习（RL）以牺牲样本多样性为代价提高了单次尝试的准确性。当基础策略产生正确解的概率接近零时，这两种策略最终都会失败：再多的采样或梯度信号也无法克服过大的搜索空间。我们采取不同的方法：不进行更困难的采样，而是通过将问题分解为更小、可独立求解的子函数（其实现可重新组合）来降低任务难度。由于现成的模型并未针对这种模块化生成进行训练，我们引入了DecompRL，这是一种明确学习分解和实现分层代码结构的RL算法。将n个模块的k个实现重新组合可产生多达k^n个候选解，从而将瓶颈从GPU推理转移到廉价的CPU评估，并将GPU令牌成本降低约50倍。在LiveCodeBench和CodeContests上（Qwen 2.5 7B, Code World Model 32B），DecompRL在每个问题超过10^5个令牌的情况下优于标准和多样性优化的RL基线，解决了标准生成无法达到的问题。

## Abstract
How can Large Language Models (LLMs) solve problems they currently cannot? Repeated sampling scales test-time compute but GPU cost grows linearly with attempts, while reinforcement learning (RL) with verifiable rewards improves single-attempt accuracy at the expense of sample diversity. Both strategies ultimately fail when the base policy has near-zero probability of producing a correct solution: no amount of sampling or gradient signal can overcome a search space that is simply too large. We take a different approach: rather than sampling harder, we make the task easier by decomposing problems into smaller, independently solvable sub-functions whose implementations can be recombined. Since off-the-shelf models are not trained for this modular generation, we introduce DecompRL, an RL algorithm that explicitly learns to decompose and implement hierarchical code structures. Recombining $k$ implementations of $n$ modules yields up to $k^{n}$ candidate solutions, shifting the bottleneck from GPU inference to cheap CPU evaluation and cutting GPU token cost by $\sim$50$\times$. On LiveCodeBench and CodeContests (Qwen~2.5~7B, Code World Model~32B), DecompRL outperforms standard and diversity-optimized RL baselines beyond $10^5$ tokens per problem, solving problems that standard generation cannot reach.

## 1. 核心问题与研究动机
- **问题**：大型语言模型（LLMs）在解决困难问题时遇到瓶颈。现有策略（重复采样、带可验证奖励的强化学习）在基础策略生成正确解的概率接近零时失效——搜索空间过大，无法通过采样或梯度信号克服。
- **动机**：不追求更努力的采样，而是**降低任务难度**：将问题分解为独立可解的子函数，重组子函数实现以指数级扩展候选解空间，从而将计算瓶颈从昂贵的GPU推理转移到廉价的CPU评估。

## 2. 方法论：DecompRL
- **核心思想**：训练两个策略——分解策略 \(\pi(D)\) 和实现策略 \(\pi(I_i|D)\)。模型首先生成由函数签名和文档字符串构成的分解计划 \(D\)（包含 \(n\) 个函数），然后为每个函数独立生成 \(k\) 个实现。通过组合所有实现得到 \(k^n\) 个完整代码候选解。
- **关键技术细节**：
  - **层级推理与重组**：利用条件独立性假设，实现之间仅通过分解计划 \(D\) 交互。重组后的轨迹数量远多于生成调用次数。
  - **强化学习目标**：采用**logmeanexp**函数作为多样本奖励聚合函数，平滑插值在平均与最大值之间，近似于 pass@1 到 pass@k 的混合目标，从而平衡探索与利用。
  - **梯度估计**：对分解策略和实现策略分别使用**留一基线（leave-one-out baseline）**来降低策略梯度方差：每个动作的优势由其参与/未参与的奖励子集计算得到。
  - **训练方式**：**顺序训练**（类似EM算法）——先固定实现策略训练分解策略（30k步），再固定分解策略训练实现策略（30k步），避免联合训练导致的熵崩溃。
- **算法流程**：
  1. 对每个问题，采样 \(d\) 个分解，每个分解最多 \(n_{\max}=6\) 个函数。
  2. 为每个函数独立采样 \(k=8\) 个实现。
  3. 从最多 \(8^n\) 种组合中随机选择 \(m=512\) 个组合进行评估（考虑广度/深度平衡）。
  4. 使用PPO（无critic）优化策略，优势计算基于logmeanexp聚合和留一基线。

## 7. 优点
- **创新性**：将层级分解与RL结合，专门训练模型以利用组合爆炸，而非单纯依靠采样或单样本优化。
- **效率**：大部分计算转移到廉价CPU，GPU token成本降低显著，适合评估快而生成贵的场景。
- **训练稳定性**：通过logmeanexp（插值平均与最大）和顺序训练（避免联合训练不稳定）实现稳定梯度估计。
- **可扩展性**：方法在更大模型（32B）上同样有效，且推理时可通过增加CPU资源直接缩放性能。

## 8. 不足与局限
- **格式税**：无RL训练时，层级推理性能低于标准全代码生成（pass@1下降3个百分点），仅在RL训练后弥补。低token预算下DecompRL不如标准推理。
- **分解大小崩溃**：训练中模型倾向于使用更少函数（图4c），可能退化为全代码生成，需通过低β的logmeanexp延缓。
- **采样时间**：训练时每问题需评估512个组合，导致worker GPU变慢并引入off-policy问题。
- **适用范围**：仅适用于天然可分解、验证成本低的领域（竞赛编程、形式化证明、硬件设计等）。不适用于难以分解或评估昂贵的任务。
- **实验覆盖**：仅针对代码竞赛，未在其他领域（如数学证明、芯片设计）进行验证。
- **局限性讨论**：论文明确承认“标准RL在基策略已足够强时更高效”，DecompRL定位为探索工具和蒸馏数据生成器，而非通用替代。
