## 摘要
自演化框架通常优化任务解决方案，同时将周围的框架视为固定的。我们引入了框架感知自演化（HASE），这是一种代理强化学习框架，其中单个模型可以在多轮动作空间中生成任务解决方案或编辑选定的框架组件。HASE使得单个Qwen3-8B模型能够匹配使用Claude Code作为框架生成器的GPT-OSS-120B模型的文本分类性能。在阿尔法因子挖掘中，HASE超越了已报道的GPT-OSS-120B基线。HASE还修复了不完善的评估组件，并在圆填充算法发现中收敛到最先进的性能。这些结果表明，HASE通过一个统一的代理过程改进了框架和解决方案。

## Abstract
Self-evolving frameworks usually optimize task solutions while treating the surrounding harness as fixed. We introduce Harness-Aware Self-Evolving (HASE), an agentic reinforcement-learning framework in which a single model can generate task solutions or edit selected harness components in a multi-turn action space. HASE enables a single Qwen3-8B model to match the text-classification performance of a GPT-OSS-120B model that uses Claude Code as the harness proposer. In alpha factor mining, HASE outperforms the reported GPT-OSS-120B baseline. HASE also repairs imperfect evaluation components and converges to state-of-the-art performance in circle-packing algorithm discovery. These results show that HASE improves the harness and the solution through one unified agentic process.

## 1. 论文的核心问题与整体含义

**研究动机与背景**  
现有自演化框架（如FunSearch、AlphaEvolve、OpenEvolve等）通常将模型周围的“框架”（Harness）视为固定不变的，仅优化对象级解决方案（如代码、算法）。所谓框架，包括提示词、记忆管理、上下文检索、工具接口、状态管理、评估器（Evaluator）等组件。这种固定假设带来两个问题：  
- 人工编写的评估器可能不完整或与真实环境不一致，模型可能在分数驱动优化下利用这些漏洞而并非解决真正任务；  
- 即使评估器正确，引导框架（如提示词）也可能提供较差的搜索先验，例如遗漏关键结构、记忆过于冗长或无关、检索策略隐藏了所需样例。  
因此，让模型能够主动改进自身工作环境（即框架）是提升性能的关键。

**整体含义**  
论文提出“框架感知的自演化”（Harness-Aware Self-Evolving，HASE）框架，使同一模型能同时生成任务解决方案和编辑选中的框架组件，实现模型权重、框架和任务解决方案的共同演化。HASE在文本分类、阿尔法因子挖掘、几何算法发现等任务上验证了有效性，仅用Qwen3-8B模型即可达到甚至超越使用大模型（GPT-OSS-120B）配合强大编码生成器（Claude Code）的系统。

## 2. 论文提出的方法论

**核心思想**  
HASE是一个基于智能体强化学习的统一框架：  
- 同一个策略模型既能提出任务解决方案，也能通过文件系统工具（如ls、cat、grep、replace、overwrite等）对框架进行读、写、修改。  
- 框架分为两类：**引导组件**（如提示词、记忆格式、检索脚本）——其编辑可自由进行，目的为改善搜索效率；**评估组件**（如验证器、评分器）——其编辑必须由真实世界评估器（不可编辑的外部环境）锚定。  
- 训练采用多轮轨迹（multi-turn trajectory）采样，最终奖励只取决于解决方案质量；框架编辑本身无直接奖励，但若编辑后产生更好的任务分数，则编辑会成为候选，在阶段边界通过审查后提交为持久框架。

**关键技术细节**  
- **统一动作空间**：模型在每一轮可以“提交解决方案”或使用沙箱命令（ls、cat、grep、replace、overwrite、done）修改框架。  
- **奖励设计**：引导组件编辑通过“概念验证”（PoC）获得信用——若编辑后轨迹分数优于当前持久框架，则加入候选池；评估组件编辑的奖励仅当代理分数与真实分数不一致时，按增加的不匹配匹配度给予。  
- **阶段式审查**：每个训练阶段包含多个GRPO（Group Relative Policy Optimization）轮次；阶段结束时，对候选编辑进行评估、筛选、提交最优持久框架。  
- **评估组件演化**：依赖不匹配集（Mismatch Set）——当代理评估器与真实评估器分数分歧时，将当前解加入不匹配集，后续补丁需修复该集合中的问题才被接受。

**算法流程（文字说明）**  
1. 初始化策略 $π_θ$、持久框架 $h_0$、本地评估器 $E_{loc}$、可选真实评估器 $E_{real}$；若允许评估组件演化，初始化不匹配集 $M$。  
2. 循环每个阶段：  
   - 初始化阶段候选池 $C_p$。  
   - 每个GRPO轮次：采样多轮轨迹，允许模型提交方案或编辑框架；使用本地评估器计算任务奖励；将编辑过引导组件且获得更高分数的轨迹加入 $C_p$；用GRPO更新策略。  
   - 若允许评估组件演化，查询真实评估器，将不匹配案例加入 $M$；审查评估组件编辑。  
   - 审查引导组件候选（过滤、排序、验证），提交最优持久框架。  
3. 重复直至收敛。

## 7. 优点

- **实用性**：仅使用8B模型即可匹敌或超越更大模型的系统，降低了部署成本和推理开销。  
- **安全性设计**：评估组件演化必须由真实世界反馈锚定，避免过度的奖励篡改；阶段审查机制防止单次“幸运补丁”直接改变持久框架。

## 8. 不足与局限

- **实验统计性不足**：阿尔法因子挖掘、圆填充、Heilbronn仅报告了单次/单种子结果，缺乏多次运行的方差和显著性检验；文本分类仅5个种子，虽已较好但可进一步扩展。  
- **可编辑组件白名单限制**：HASE只允许编辑事先指定的组件，对于更复杂的框架（如多工具、多智能体协作）是否适用待验证。  
- **评估组件演化依赖真实反馈**：需要可连续查询的真实评估器，在计算或经济成本高的场景下可能不可行；且仅修复当前不匹配集，无法保证完全正确的评估器。

- **训练超参数可能未充分调优**：每个域使用固定算法设置（如3阶段、3轮次），最优性未知。  
- **应用限制**：涉及金融阿尔法因子挖掘，虽有审计控制，但模型可能仍存在过拟合风险（尽管用了Qlib模拟器和多种频率指标）。
