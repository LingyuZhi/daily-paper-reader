## 摘要
最近的LLM智能体处理越来越长视野、开放式的任务，而外部技能——提供给智能体的可重用程序性知识——进一步扩展了这种能力。然而，固定的、手工编写的技能很少是最优的，也无法适应智能体遇到的任务多样性。自我改进的智能体通过从执行轨迹中重写自己的技能文件来应对这一问题，在具有挑战性的基准测试中取得了有意义的增益。然而，这种自我进化仍然是非递归的：它只改进任务技能（智能体做什么），而改进过程（如何改进）是一次性编写并保持固定的。我们引入MetaSkill-Evolve，一个双时间尺度框架，使智能体技能改进变得递归：每个分支都携带一个任务技能$s$和一个分支局部元技能$m=(ψ,σ,α,π,\varepsilon)$，其五个组件分别参数化了改进流程中的分析器、检索器、分配器、提议器和进化器。任务技能在快速循环中进化，而元技能在同一流程应用于自身的情况下以较慢速度进化，无需额外的模型或目标。在五个流程智能体共享单个冻结主干的情况下，MetaSkill-Evolve在三个智能体基准测试（OfficeQA、SealQA、ALFWorld）上超越了无技能、静态技能和单级进化基线，分别将原始主干上的保留测试准确率提高了+23.54、+16.09和+1.92个百分点。

## Abstract
Recent LLM agents tackle increasingly long-horizon, open-ended tasks, and external skills, reusable procedural knowledge supplied to the agent, further extend this capability. However, a fixed, hand-authored skill is rarely optimal, and cannot adapt to the diversity of tasks an agent encounters. Self-improving agents address this by rewriting their own skill files from execution traces, yielding meaningful gains on challenging benchmarks. Yet such self-evolution remains non-recursive: it improves only the task skill (what the agent does) while the improvement procedure (how it improves) is authored once and held fixed. We introduce MetaSkill-Evolve, a two-timescale framework that makes agentic skill improvement recursive: every branch carries both a task skill $s$ and a branch-local meta-skill $m=(ψ,σ,α,π,\varepsilon)$ whose five components parameterise the Analyzer, Retriever, Allocator, Proposer, and Evolver agents of the improvement pipeline. Task skills evolve on a fast loop while the meta-skill evolves on a slower one under the same pipeline applied to itself, with no additional model or objective. With all five pipeline agents sharing a single frozen backbone, MetaSkill-Evolve outperforms no-skill, static-skill, and single-level evolution baselines on three agentic benchmarks (OfficeQA, SealQA, ALFWorld), improving held-out test accuracy over the raw backbone by +23.54, +16.09, and +1.92 points respectively.

## 2. 论文提出的方法论：核心思想、关键技术细节

- **核心思想**：提出**MetaSkill-Evolve**框架，采用双时间尺度进化。每个分支携带一个**分支状态** `b = (s, m, h)`：
  - `s`：任务技能（task skill），Markdown格式的LLM智能体程序，指定任务的过程、工具和启发式方法。
  - `m`：分支级**元技能**（meta-skill），`m = (ψ, σ, α, π, ε)`，五个组件分别参数化了改进管道中的五个智能体：
    - ψ（诊断策略，对应Analyzer）：将失败映射为标签ϕ和自由形式分析a。
    - σ（共享策略，对应Retriever）：根据标签ϕ选择同分支和跨分支的灵感。
    - α（分配策略，对应Allocator）：设置每步子代预算K∈[1, Kmax]。
    - π（编辑提议策略，对应Proposer）：基于失败、分析和灵感生成具体编辑δ。
    - ε（编辑执行策略，对应Evolver）：将δ写入磁盘并验证结果。
  - `h`：分支迭代历史。
- **关键技术细节**：
  - **两个时间尺度**：
    - **快循环（Fast Loop）**：每次迭代更新任务技能s。流程：恢复父分支的快照→评估训练批次→选取最差失败样本→Analyzer诊断→Retriever获取灵感→Allocator分配子代预算→Proposer生成K个编辑→Evolver应用并验证→评估子代在验证集上的效用ΔU→提交节点到DAG。
    - **慢循环（Slow Loop）**：每H次快循环后更新元技能m。使用相同的五智能体管道，但输入为合成元失败轨迹（整合最近H个子代的标签、诊断和结果），目标对象从任务技能文件切换为元技能文件。所有五个元技能文件被协同重写（Proposer按顺序编辑每个组件，Evolvers并行写入）。
  - **持久化进化图（DAG）**：所有历史节点存储在SQLite DAG中，每个节点存储(s, m, U, ΔU, ϕ)等信息。只有严格优于父代（ΔU>0）的子代进入存档（可被选为父代），但所有节点都保留并提供跨分支检索。
  - **前沿选择（Frontier Selection）**：每次迭代从存档中选择前K个节点，得分公式：
    ```
    v* = argmax_v∈F [η1 * Uv + η2 * P̂v + η3 * Nv]
    ```
    - Uv：任务效用（验证集准确率）
    - P̂v：元生产力估计（平均每子代改进量）
    - Nv = 1/(1 + times_selected_v)：冷却因子，防止预算垄断
  - **递归自改进**：由于元技能组件本身也是Markdown格式的技能文件，与任务技能格式完全相同，因此同一管道可以递归地应用于元技能本身。这是有边界的单层递归（meta-skill evolution on meta-skill），无需额外模型或训练目标。
  - **五智能体管道**：比传统analyze→propose→evolve多了Retriever（跨分支共享）和Allocator（自适应子代预算）。
