## 摘要
推理上下文长度与强化学习后训练之间的差距日益扩大：推理系统正接近百万token的上下文，而后训练工作负载通常仍保持在256K token或以下，并依赖部署时的长度泛化。这一差距对AI智能体尤为重要，因为其观察、工具输出、文档和先前的决策会在长轨迹中累积。LongStraw是一个在固定GPU预算下进行百万token强化学习后训练的结构感知执行栈，通过分组相对策略优化（GRPO）实现。它在无自动求导的情况下评估共享提示，仅保留后续token所需的模型特定状态，并逐一重放短响应分支，以额外的重放时间换取更紧凑的训练计算图。我们为混合循环与全注意力机制的Qwen3.6-27B以及压缩注意力混合专家模型GLM-5.2实现了该方法。在8块H20 GPU上，LongStraw在2.1M位置上完成分组Qwen评分和响应反向传播，组大小分别为2和8；增加组大小仅增加0.21 GB的峰值分配内存，而单独的压力测试达到了4.46M位置。在32块H20 GPU上，我们验证了GLM-5.2全部78层上2.1M token提示的端到端LongStraw执行路径。这些实验确立了执行能力而非完整的训练正确性，因为捕获的提示状态是分离的，且部分分布式前向和梯度组合路径仍不完整。

## Abstract
A growing gap separates inference context lengths from RL post-training: inference systems are approaching million-token contexts, while post-training workloads often remain at 256K tokens or below and rely on length generalization at deployment. The gap is especially important for AI agents, whose observations, tool outputs, documents, and prior decisions accumulate over long trajectories. LongStraw is an architecture-aware execution stack for million-token RL post-training under a fixed GPU budget, instantiated with Group Relative Policy Optimization (GRPO). It evaluates the shared prompt without autograd, retains only model-specific state needed by later tokens, and replays short response branches one at a time, reducing the live training graph at the cost of additional replay time. We implement it for the hybrid recurrent and full-attention Qwen3.6-27B and the compressed-attention mixture-of-experts GLM-5.2. On eight H20 GPUs, LongStraw completes grouped Qwen scoring and response backward at 2.1M positions for groups of 2 and 8; increasing the group size adds only 0.21 GB of peak allocated memory, while a separate stress test reaches 4.46M positions. On 32 H20 GPUs, we validate the end-to-end LongStraw execution path for a 2.1M-token prompt across all 78 layers of GLM-5.2. These experiments establish execution capacity rather than complete training correctness because the captured prompt state is detached and some distributed forward and gradient composition paths remain incomplete.

## 1. 论文的核心问题与整体含义（研究动机和背景）

- **核心问题**：当前大型语言模型的推理系统已能支持近百万token的上下文长度，但强化学习后训练（如GRPO）时，训练上下文的长度通常仍被限制在256K token以下，依赖部署时的长度泛化。这种差距严重限制了AI智能体在长轨迹（如工具调用、文档阅读、多步决策）上的学习效果。
- **整体含义**：作者指出，训练不仅需要前向计算，还需对同一历史下的多个响应进行评分和反向传播，且二次注意力和长时间的反向状态导致GPU显存成为主要瓶颈。LongStraw旨在**在固定GPU预算下**实现百万token级别的RL后训练，从而降低硬件门槛，让更多研究者和团队在有限加速器下探索长上下文智能体训练。

## 2. 论文提出的方法论：核心思想、关键技术细节

### 核心思想
- **“捕获一次，重放后缀”**：将长提示（prompt）与短响应（response）计算分离。共享提示仅在不开启自动求导（autograd）的情况下评估一次，存储模型特定的状态（如注意力KV页、循环状态、压缩潜在表示等），然后逐个短响应分支在autograd下重放，累积梯度后再调用优化器。从而将在线训练图从整个提示+响应序列缩小为单个响应分支。

### 关键技术细节
- **架构感知状态保留**：对于Qwen（混合循环+全注意力模型），保留循环状态（GDN，固定大小）和16层全注意力的紧凑KV页；对于GLM（压缩注意力MLA/DSA + MoE），在CPU上保留MLA潜在页和DSA索引键页，每次重放时只将一层所需的页面加载到GPU。
- **分组相对策略优化（GRPO）执行顺序**：
  - 阶段1：无梯度提示捕获。
  - 阶段2：冻结旧策略和参考策略的评分（GLM统一完成，Qwen逐成员）。
  - 阶段3：逐个成员重放响应分支，进行前向和反向，累积梯度。
  - 阶段4：完成所有成员后，执行一次优化器调用。
- **全局全注意力前向合成**：Qwen使用CP8上下文并行，通过取最大对数、求和等操作在秩间合成全局softmax输出。
- **全层检查点（Whole-Layer Checkpointing）**：GLM中，在重放的响应分支上对整个解码器层进行激活检查点，前向仅保留输入和元数据，反向时重新计算，避免保留MoE路由、专家激活等中间结果。
- **物理页所有权**：逻辑分片必须对应物理释放——将每个秩拥有的页复制到独立分配的内存块中，使分配器所有权与页表所有权一致，从而释放页时真正释放内存。

### 公式说明（文字表述）
- 使用了GRPO的裁剪重要性比率损失，包含KL正则项。
- 论文指出，由于提示状态被分离（stopgrad），计算得到的梯度只包含响应分支对参数的依赖，缺少通过提示状态传播的梯度项（第二项）。因此LongStraw不声称与全序列梯度等价。

## 6. 论文的主要结论与发现

- **主要结论**：在固定GPU预算下实现百万token GRPO后训练是可行的，关键在于**张量生命周期和所有权管理**，而非仅靠稀疏性或注意力优化。通过将长提示与短响应分离，显存主导从提示长度变为响应长度，组大小被转化为调度维度而非容量维度。
- **发现**：
  - Qwen在8个H20上达到2.1M（G=8）和4.25M（G=8，仅响应重放/前缀冻结多步）执行容量。

  - 组大小从2增至8，峰值显存仅增0.21 GB（Qwen），验证了串行响应的内存优势。
  - 物理所有权（页复制而非视图）是显存缩减的关键；上下文并行与专家并行是正交维度，不能互相替代。
  - 4.25M的Qwen执行进一步将界推到8×原始位置设置。
